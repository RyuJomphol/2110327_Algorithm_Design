# 🚫 Table without 11 (ตารางที่ไม่มี 1 ติดกัน)

## 1. วิเคราะห์โจทย์ Table without 11
โจทย์กำหนดให้มีตารางขนาด 2 แถว และ $n$ คอลัมน์ (ขนาด $2 \times n$) ซึ่งเราต้องเติมตัวเลข `0` หรือ `1` ลงในแต่ละช่อง 
โดยมีข้อห้ามสำคัญคือ **"ห้ามมีเลข 1 อยู่ติดกัน"** (แบ่งเป็น ห้ามติดกันในแนวนอน และห้ามติดกันในแนวตั้งขอบชิดขอบ) แต่สามารถอยู่เฉียงกันได้ 
เราต้องการหาว่ามีจำนวณตารางที่เป็นไปได้ทั้งหมดกี่รูปแบบสำหรับขนาด $n$ คอลัมน์ และเพื่อให้ค่าไม่ล้นเกินขีดจำกัดจำนวนเต็ม จึงให้ตอบเป็นผลลัพธ์การ Modulo ด้วย `100,000,007`

โจทย์ที่มีการห้ามจัดเรียงลักษณะนี้ สามารถใช้เทคนิค **Dynamic Programming** ประเภท State Machine ในการยุบสถานะ (State) ของคอลัมน์ให้อยู่ในรูปแบบที่จัดการง่ายได้

## 2. วิเคราะห์ที่มาสมการ Recurrence Relation
สำหรับตารางขนาด 2 แถว ใน 1 คอลัมน์ใดๆ จะสามารถเติมตัวเลขได้เพียง 3 รูปแบบที่เป็นไปได้และไม่ผิดกฎแนวตั้งเลย คือ:
1. `[0, 0]` คือ บน `0` ล่าง `0`
2. `[1, 0]` คือ บน `1` ล่าง `0`
3. `[0, 1]` คือ บน `0` ล่าง `1`
*(รูปแบบ `[1, 1]` เอามาใช้ไม่ได้ เพราะจะทำให้เลข 1 ติดกันในแนวตั้งทันที)*

เมื่อพิจารณาความน่าจะเป็นในการเชื่อมต่อคอลัมน์ปัจจุบัน (State ปัจจุบัน) ต่อจากคอลัมน์ก่อนหน้า (State อดีต) เราจะกำหนดตัวแปรให้:
* ให้ $a$ แทน จำนวนรูปแบบตารางที่คอลัมน์ท้ายเป็น `[0, 0]`
* ให้ $b$ แทน จำนวนรูปแบบตารางที่คอลัมน์ท้ายเป็น `[1, 0]`
*(ส่วนกรณี `[0, 1]` เนื่องจากมีความสมมาตรบนล่างกับ `[1, 0]` จำนวนรูปแบบของสายนี้จึงมีค่าเป็น $b$ เท่ากันเสมอ เราจึงคำนวณอันเดียวก็พอ)*

**สมการ Recurrence Relation สำหรับคอลัมน์ที่ $i$:**
* `next_a = a + 2*b`: คอลัมน์ใหม่ที่จบด้วย `[0, 0]` ปลอดภัยร้อยเปอร์เซ็นต์ มันจึงสามารถไปต่อท้ายคอลัมน์เก่าที่เป็นรูปแบบไหนก็ได้ ทั้ง `[0, 0]` ($a$ แบบ), `[1, 0]` ($b$ แบบ) และ `[0, 1]` อีก ($b$ แบบ) 
* `next_b = a + b`: คอลัมน์ใหม่ที่จบด้วย `[1, 0]` ข้างบนมี 1 ทำให้**ห้ามไปต่อท้าย**คอลัมน์เก่าที่มี 1 ข้างบนเหมือนกัน (`[1, 0]`) มันจึงไปต่อได้แค่กัับ `[0, 0]` ($a$ แบบ) หรือสลับที่กับ `[0, 1]` ($b$ แบบเฉียงๆ) เท่านั้น

**ผลรวมรูปแบบทั้งหมดของความยาว $n$ คอลัมน์:**
เกิดจากการนำทุกรูปแบบที่เป็นไปได้มารวมกัน คือรูปแบบที่จบด้วย `[0, 0]` ($a$ วิธี) รวมกับ `[1, 0]` ($b$ วิธี) และ `[0, 1]` ($b$ วิธี) 
ดังนั้น คำตอบสุดท้ายคือ `a + 2*b`

## 3. อธิบายโค้ดและยกตัวอย่าง Testcase
**การทำงานของโค้ด:**
1. โปรแกรมรับค่าจำนวนคอลัมน์ `n` และมีตัวแปรมอดุโล `MOD = 100000007` ควบคุมผลลัพธ์
2. กำหนด Base cases ในคอลัมน์ที่ 1 ว่ามีจำนวนวิธีที่เป็นไปได้คือ `a = 1` รูปแบบ, และ `b = 1` รูปแบบ 
3. สร้างวงลูป `for` เพื่อจำลองการต่อตารางตั้งแต่คอลัมน์ `i = 2` ไปจนถึงคอลัมน์ที่ `n`
   * ในแต่ละรอบ จะมีการคำนวณค่า $a$ ถัดไป (`next_a`) และค่า $b$ ถัดไป (`next_b`) ตามกฎ State machines ที่ตั้งไว้
   * โดยทุกการบวกจะถูกคลุมด้วย `% MOD` เพื่อป้องกันการเกิด Integer Overflow
   * ทำการนำค่าเจเนอเรชันถัดไปบันทึกทับค่าเจเนอเรชันเก่า `a = next_a; b = next_b;` เตรียมไว้รอบหน้า
4. เมื่อลูปขยายจนมาถึงขอบตารางที่ $n$ ทำการหาคำตอบรวม `ans = (a + 2 * b) % MOD` แล้วปริ้นออก 

**ยกตัวอย่าง Testcase:**
**Input:** $n=15$
**ทำ Trace สั้นๆ ให้เห็นภาพ:**
* $i=1$: `a=1`, `b=1` 
   *(ผลรวมรอบนี้ $= 1 + 2(1) = 3$ รูปแบบ)*
* $i=2$: 
   `next_a = 1 + 2(1) = 3`
   `next_b = 1 + 1 = 2`
   อัปเดตสถานะ: `a=3`, `b=2`  
   *(ผลรวมรอบนี้ $= 3 + 2(2) = 7$ รูปแบบ)*
* $i=3$:
   `next_a = 3 + 2(2) = 7`
   `next_b = 3 + 2 = 5`
   อัปเดตสถานะ: `a=7`, `b=5` 
   *(ผลรวมรอบนี้ $= 7 + 2(5) = 17$ รูปแบบ)*
* กระบวนการนี้ลูปวนไปจนกว่าตารางจะยาวถึงคอลัมน์ที่ $i=15$ จะได้ตัวแปร $a$ และ $b$ ก้อนใหญ่มาก เมื่อนำมาคำนวณ [(a + 2*b) % 100000007](cci:1://file:///c:/Users/fangj/OneDrive/Documents/Algorithm/Rope/rope.cpp:6:0-25:1) แล้วจะได้ **Output: 665857** ตามโจทย์คาดหวังแบบพอดิบพอดี

## 4. Time Complexity
**ความซับซ้อนด้านเวลา (Time Complexity):** **$O(n)$**
เหตุผล: การแก้โจทย์ในวิธีดังกล่าว เราวิเคราะห์ปัญหาให้อยู่ในรูปสมการแล้ว และใช้ลูปแค่ระดับชั้นเดียวที่ความยาวแปรผันผูกตามจำนวนของ $n$ โดยในแต่ละลูปทำการประมวลผลพื้นฐานทั้งการบวกและการใช้ Modulo แค่สเต็ปสองสเต็ป ($O(1)$ ต่อรอบ) ส่งผลให้ระดับความเร็วการทำงานของมันเป็น Linear Time ซึ่งค่อนข้างเต็มประสิทธิภาพแบบ 100% ตอบโจทย์ $n$ จำนวนมหาศาลได้อย่างรวดเร็ว

*(เพิ่มเติม)*
**ความซับซ้อนด้านพื้นที่ (Space Complexity):** **$O(1)$**
เหตุผล: การแก้ปัญหาที่ไม่ได้นำค่าอดีตใดๆ นอกเสียจาก 1 ขั้นล่าสุดมาใช้ ทำให้เราลดขนาดพื้นที่ด้วยการใช้ตัวแปรแค่ $a$ และ $b$ ในหน่วยความจำ ไม่ต้องกาง Array ใหญ่ๆ ตามความยาวของขนาด $n$ ทำให้เบาเครื่องมากๆ
