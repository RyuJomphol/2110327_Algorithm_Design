# Tile

## 1. วิเคราะห์โจทย์ Tile
มีกระเบื้องสี่เหลี่ยม `N` แผ่น แผ่นที่ `i` มีความกว้าง `A[i]` (พื้นที่ = `A[i]²`)
ผลรวมพื้นที่ปัจจุบัน = `Σ(A[i]²)`

องค์กรมีโปรโมชันพิเศษ: สามารถแลกกระเบื้องแต่ละแผ่น `A[i]` ด้วยกระเบื้องใหม่ที่มีความกว้าง `B[i]` (จำนวนเต็มบวกใดก็ได้)
ค่าใช้จ่ายของการแลก = `|A[i] - B[i]|²`
เงื่อนไข: 
- ถ้าแลกแผ่นใดไป ไม่สามารถแลกมาใหม่ได้ (แต่ละแผ่นแลกได้ครั้งเดียวเท่านั้น)
- ไม่สามารถแลกแล้ว ยกเลิกคำสั่ง

เป้าหมาย: หาเงินน้อยที่สุดเพื่อแลกกระเบื้องให้ผลรวมพื้นที่เท่ากับ `M`
ถ้าไม่มีวิธีแลกที่ให้ผลรวมเป็น `M` ให้ตอบ `-1`

---

## 2. วิเคราะห์ที่มาสมการ Recurrence Relation
นิยามสถานะ DP:
- `dp[j]` = เงินน้อยที่สุดเพื่อให้ผลรวมพื้นที่เท่ากับ `j`

ฐาน:
```
dp[0] = 0       (ไม่มีกระเบื้อง = 0 บาท)
dp[j] = INF     untuk j > 0 (เริ่มต้น)
```

สำหรับแต่ละกระเบื้อง `i` ที่มีความกว้างเดิม `A[i]` เรามีตัวเลือก:
1. **ไม่แลก**: เพิ่มพื้นที่ `A[i]²` โดยไม่มีค่าใช้จ่าย
   - ถ้า `j + A[i]² ≤ M`: `dp[j + A[i]²] = min(dp[j + A[i]²], dp[j])`

2. **แลกเป็น `B`** (B = 1, 2, ..., √M):
   - เพิ่มพื้นที่ `B²` ด้วยค่าใช้จ่าย `|A[i] - B|²`
   - ถ้า `j + B² ≤ M`: `dp[j + B²] = min(dp[j + B²], dp[j] + |A[i] - B|²)`

เนื่องจาก `B² ≤ M` ซึ่งหมายถึง `B ≤ √M` ดังนั้นจึงมีจำนวน `B` ที่มีขอบเขต

คำตอบสุดท้าย: `dp[M]` (ถ้า `dp[M] < INF` แสดงว่ามีวิธี มิฉะนั้นตอบ `-1`)

## 3. อธิบายโค้ด + ยกตัวอย่าง testcase
วิธีการทั่วไป:
```
dp[0] = 0
for j = 1..M: dp[j] = INF

for each tile i = 1..N:
  for j = M down to 0:        // วนย้อนหลังเพื่อหลีกเลี่ยงการใช้ค่าที่เพิ่งอัพเดต
    
    // ตัวเลือก 1: ไม่แลกแผ่น i
    if j + A[i]² ≤ M:
      dp[j + A[i]²] = min(dp[j + A[i]²], dp[j])
    
    // ตัวเลือก 2: แลกแผ่น i เป็นขนาด B
    for B = 1 to sqrt(M):
      if j + B² ≤ M:
        cost = |A[i] - B|²
        dp[j + B²] = min(dp[j + B²], dp[j] + cost)

answer = (dp[M] < INF) ? dp[M] : -1
```

### Testcase
อินพุต:
```
3 6
3
3
1
```
- `N = 3`, `M = 6`
- `A = [3, 3, 1]`
- พื้นที่ปัจจุบัน = `9 + 9 + 1 = 19`

ผลลัพธ์จากตัวอย่าง:
- แลกกระเบื้อง 1 (A=3) → B=2: ค่า `|3-2|² = 1`, พื้นที่เพิ่ม `4`
- แลกกระเบื้อง 2 (A=3) → B=1: ค่า `|3-1|² = 4`, พื้นที่เพิ่ม `1`
- ไม่แลกกระเบื้อง 3 (A=1): ค่า `0`, พื้นที่ `1`
- รวมพื้นที่: `4 + 1 + 1 = 6` ✓
- รวมค่าใช้จ่าย: `1 + 4 + 0 = 5` ✓

**ผลลัพธ์: 5**

## 4. Time Complexity
- สำหรับแต่ละกระเบื้อง (N) เราต้องวนผ่านพื้นที่ทั้งหมด (M)
- สำหรับแต่ละพื้นที่ เราสำรวจขนาด B ที่เป็นไปได้ (ประมาณ √M)

**เวลา**: `O(N * M * √M)`

ในกรณีทั่วไปเมื่อ M ไม่ใหญ่มากนัก (เช่น M ≤ 10^6) ความซับซ้อนนี้อยู่ในช่วงที่ยอมรับได้

**พื้นที่**: `O(M)` สำหรับอาเรย์ `dp`

## สรุป
ปัญหา Tile เป็นตัวแปรของ Knapsack ที่เพิ่มมิติ "การเลือกค่าใหม่" (`B`) สำหรับแต่ละรายการ
ใช้ DP 1 มิติที่แสดงถึงผลรวมพื้นที่และหาค่าใช้จ่ายอย่างน้อยที่สุด
แนวคิดคือ "เลือกไม่แลก หรือแลกเป็นค่า B ใดค่า B หนึ่ง" สำหรับแต่ละกระเบื้อง
