# ↔️ One Two Apart (หนึ่งสองต้องห่างกัน)

## 1. วิเคราะห์โจทย์ One Two Apart
เราต้องการสร้างอาเรย์ความยาว $n$ โดยให้แต่ละช่องสามารถเติมเลข `0`, `1`, หรือ `2` เท่านั้น
มีกฎข้อบังคับที่สำคัญคือ: **"ช่องที่มีเลข 1 ต้องอยู่ห่างจากช่องที่มีเลข 2 อย่างน้อย 2 ช่อง"** 
กล่าวคือ ถ้าระบุว่ามีเลข 1 อยู่ สิ่งที่ห้ามเกิดเด็ดขาดคือการมีเลข 2 ไปปรากฏอยู่ในระยะที่ห่างออกไปแค่ 1 หรือ 2 ช่องนั่นเอง (`...12...`, `...21...`, `...102...`, `...201...` พวกนี้ถือว่าผิดกฎทั้งหมด)
เราต้องการทราบจำนวนรูปแบบความน่าจะเป็นในการเติมตัวเลขลงอาเรย์ที่ถูกต้องว่ามีกี่รูปแบบ โดยให้ตอบเป็นผลลัพธ์ Modulo 100,000,007 

โจทย์ข้อนี้เป็นกรณีคลาสสิกของ Dynamic Programming แบบ **State Machine** ซึ่งเราสามารถแบ่งและยุบรวมสถานะ (State) ของลำดับตัวเลขที่กำลังสร้างอยู่ได้ เพื่อหลีกเลี่ยงผลกระทบจากการจัดเรียงตัวเลขที่ผิดกฎ

## 2. วิเคราะห์ที่มาสมการ Recurrence Relation
ในปัญหาข้อนี้ เราอาศัยสมบัติ**ความสมมาตร (Symmetry)** ของการวางเลข `1` และ `2` หมายความว่าจำนวนรูปแบบใดๆ ที่เกิดของฝั่งเลข `1` ก็จะเกิดในปริมาณเท่ากันเป๊ะกับฝั่งเลข `2` 
ดังนั้น เราสามารถประมวลผลแค่ฝั่ง `1` เป็นตัวทำสถิติหลัก แล้วค่อยนำไปคูณสองตอนจบ เพื่อคำนวณรวบยอดแทนฝั่งเลข `2` ด้วยได้เลย 

เราสามารถนิยามหรือจัดกลุ่มย่อยของ "ลำดับความยาว $i$" ไว้ 3 สถานะ ดังนี้:
1. **สถานะ A:** อาเรย์ที่ลงท้ายด้วยตัวเลข `1` (มีจำนวนวิธี $A$ แบบ)
2. **สถานะ B:** อาเรย์ที่ลงท้ายด้วยตัวเลข `0` แต่ตัวก่อนหน้าคือ `1` เช่น `...10` (มีจำนวนวิธี $B$ แบบ) ซึ่งสถานะนี้ "ยังไม่ปลอดภัย" หากรอบหน้าเผลอเอา `2` มาต่อท้าย จะผิดกฎทันที
3. **สถานะ C:** อาเรย์ที่ "ปลอดภัย" (Safe State) หมายถึง อาเรย์ที่ลงท้ายด้วยประวัติสะอาด เช่น `...00` หรือมีแค่ `0` มาตั้งแต่เริ่ม ไม่ว่าเราจะเอา 1 หรือ 2 มาต่อท้ายก็จะไม่ละเมิดกฎระยะห่างแน่นอน (มีจำนวนวิธี $C$ แบบ)

**สมการ Recurrence Relation (การขยับสร้างไปสู่ความยาว $i+1$):**
* `nextA = (A + B + C) % MOD` 
  หากเราต้องการให้ลำดับใหม่จบด้วย `1` เราสามารถเอา `1` ไปต่อท้ายชุดแบบไหนก็ได้ (เพราะ `1` ล้วงต่อหลัง `1` หรือ `0` ได้อย่างอิสระ ไม่ผิดเงื่อนไขอะไร)
* `nextB = A % MOD`
  หากเราต้องการสร้างลำดับที่ลงท้ายด้วย `10` เราต้องเอาลำดับความยาวเดิมที่จบด้วย `1` (สถานะ $A$) มาต่อด้วยเลข `0` เท่านั้น
* `nextC = (C + 2*B) % MOD`
  การจะสร้างลำดับใหม่ที่มั่นคงความปลอดภัย `00` เราสามารถนำความปลอดภัยเดิม (สถานะ $C$) มาเติม `0` 
  รวมกับกรณีที่เราเอาสถานะ $B$ (ที่ลงท้ายด้วย `...10`) มาเติม `0` ให้กลายเป็น `...100` (ซึ่งมีระยะห่าง 3 ช่องแล้ว พ้นขีดอันตราย) และต้องอย่าลืมคุณสมบัติความสมมาตรของเคสฝั่ง `...20` ด้วย จึงต้องคูณ 2 ได้เป็น `2 * B`

## 3. อธิบายโค้ดและยกตัวอย่าง Testcase
**การทำงานของโค้ด:**
1. โปรแกรมรับค่า $n$ ซึ่งเป็นความยาวของอาเรย์มา 
2. ตัวแปรเก็บมอดุโล `MOD = 100000007`
3. กรณีฐาน `n = 1`: ผลลัพธ์คือตัวมันเองเดี่ยวๆ 3 ทาง (ได้ 0, 1, 2) โปรแกรมจะปริ้นท์ 3 และจบการทำงาน
4. สำหรับ $n \ge 2$, ให้กำหนด Base cases ตอนความยาวเป็น 1 คือ: 
   * `A = 1` (จำนวนแบบที่จบด้วย 1)
   * `B = 0` (ยังไม่มีตัวเลขประกอบสองหลัก จึงไม่มีอันที่จบด้วย 10)
   * `C = 1` (จำนวนแบบที่จบด้วย 0 อย่างปลอดภัย)
5. เริ่มเข้าวงลูป `for (int i = 2; i <= n; i++)`:
   * จะทำการจำลองต่อท้ายเลขไปเรื่อยๆ เพื่อนำสถานะในอดีต `A, B, C` มาผ่านสมการ State Machine โค้ดมีการสั่ง Modulo `% MOD` ประกบทุกรอบเพื่อไม่ให้เลขล้นเกินขอบเขต 
   * อัปเดตตัวแปรทับเพื่อให้พร้อมในการรันไปสู่บรรทัดความยาวถัดไป
6. แสดงผลลัพธ์: ลูปสิ้นสุดการเจริญเติบโตเมื่อความยาวชนขอบ $n$ ยอดคำตอบสุทธิก็คือการเอาจำนวนจาก 3 กลุ่มสถานะมารวมกัน นั่นคือ `ans = (2 * A) + (2 * B) + C` (เราทำการคูณ 2 ที่ $A$ และ $B$ เพื่อทบผลรวมของฝั่งที่จบด้วยตัวเลขหลัก `2` เอาไว้อย่างสมมาตรตามที่อธิบาย)

**ยกตัวอย่าง Testcase:**
**Input:** `15` ($n=15$)
**การวิเคราะห์ State รายรอบแบบรวบรัด:**
* $i=1$: `A=1`, `B=0`, `C=1`
* $i=2$: 
  * `nextA = 1+0+1 = 2`
  * `nextB = 1`
  * `nextC = 1+0 = 1`
  *(รอบนี้ยอดรวมจะเป็น: 2(2) + 2(1) + 1 = 7)*
* $i=3$:
  * `nextA = 2+1+1 = 4`
  * `nextB = 2`
  * `nextC = 1+(2*1) = 3`
  *(รอบนี้ยอดรวมจะเป็น: 2(4) + 2(2) + 3 = 15)*
* ระบบจะทำการทดและบวกร่วมไปเรื่อยๆ ตามวงลูป เมื่อถึง $i=15$ สมบูรณ์ ระบบจะประมวลผลออกมาได้ค่าคำตอบ **Output: 198799** ในท้ายที่สุด 

## 4. Time Complexity
**ความซับซ้อนด้านเวลา (Time Complexity):** **$O(N)$**
เหตุผล: การแก้โจทย์ในวิธีดังกล่าว เราไม่ได้ทำงานไปจนถึงเวลาสร้างทรีรูปแบบที่เป็นไปได้จริงทั้งหมด $3^N$ แต่ใช้วิธียุบรวมสถานะต่างๆ แล้วเดินลูปเพียง 1 ชั้นที่แปรผันผูกตามจำนวนรอบแบบเส้นตรง $N$ ครั้ง ภายในลูปก็จะมีการบวกเลขและ %MOD ด้วยปริมาณคงที่ (Constant Operations - $O(1)$) จึงมีความซับซ้อนตกอยู่ในหมวด Linear Time อย่างแท้จริง

*(เพิ่มเติม)*
**ความซับซ้อนด้านพื้นที่ (Space Complexity):** **$O(1)$**
เหตุผล: การเขียนโปรแกรมสำหรับแก้ปัญหานี้ใช้พื้นที่แบบคงที่โดยสมบูรณ์ ไม่มีการสร้าง Array หรือ Vector กักเก็บค่า $A, B, C$ รายตัวเอาไว้แต่อย่างใด โปรแกรมประกาศแค่ตัวแปรจำนวนหยิบมือในการจำค่าเฉพาะของความยาวรอบปัจจุบัน ช่วยประหยัด Memory Limit ลงไปได้อย่างมหาศาล
