# ⚡ Quick Sum (ผลรวมช่วงตารางอย่างรวดเร็ว)

## 1. วิเคราะห์โจทย์ Quick Sum
โจทย์กำหนดตาราง 2 มิติ (2D Array) $A$ ขนาด $N$ แถว และ $M$ คอลัมน์ เป้าหมายคือต้องการให้เราหา "ผลรวมของกลุ่มตัวเลขในตาราง (Block Summation)" ตั้งแต่พิกัดเริ่มต้นมุมซ้ายบนที่ `(r1, c1)` ลากเป็นพื้นที่สี่เหลี่ยมไปจนถึงมุมขวาล่างที่พิกัด `(r2, c2)` 

สิ่งที่เป็นความท้าทายคือ เราจะต้องตอบคำถามการหาผลรวมพื้นที่แบบนี้จำนวนทั้งหมด $K$ คำถาม
วิธีแบบปกติ (Naïve approach) คือถ้ามีคำถามมา 1 ครั้ง เราก็ใช้ลูป `for` 2 ชั้น ไล่บวกทีละช่องไปเรื่อยๆ ซึ่งแต่ละคำถามมีโอกาสเกิดรอบการบวกสูงสุด $N \times M$ ครั้ง ถ้านับรวมตลอด $K$ คำถามอาจใช้เวลาขยายขนาดบานปลายจน Time Limit Exceeded (TLE) ได้ 

ด้วยเหตุนี้ เราจึงควรใช้เทคนิค **2D Prefix Sum (ผลรวมสะสม 2 มิติ)** เพื่อทำ Pre-calculation ก่อนเพียง 1 ครั้ง หลังจากนั้นไม่ว่าโจทย์จะโยนขอบเขตช่องแบบไหนมา ก็จะสามารถตอบหาผลรวมของพื้นที่นั้นๆ ได้ทันทีในเวลาเสี้ยววินาที หรือ $O(1)$ ต่อหนึ่งคำถาม

## 2. วิเคราะห์ที่มาสมการ Recurrence Relation
**ขั้นที่ 1: การสร้างตาราง Prefix Sum**
ให้ `P(i, j)` คือผลรวมสะสมตั้งแต่พิกัด `(0,0)` มาจนถึงจุดพิกัดจุดปลายที่ `(i,j)` โดยครอบคลุมพื้นที่สี่เหลี่ยมนี้ทั้งหมด การจะคำนวณ `P(i, j)` โดยใช้หลักการ Dynamic Programming ทำได้โดยนำข้อมูลผลรวมพื้นที่ก่อนหน้ามาประกอบกัน (Inclusion-Exclusion Principle):
* **Recurrence Relation:** `P[i][j] = A[i][j] + P[i-1][j] + P[i][j-1] - P[i-1][j-1]`
  * `A[i][j]` คือค่าช่องปัจจุบัน
  * `P[i-1][j]` คือพื้นที่สี่เหลี่ยมด้านบนที่คำนวณไว้แล้ว
  * `P[i][j-1]` คือพื้นที่สี่เหลี่ยมด้านซ้ายที่คำนวณไว้แล้ว
  * เนื่องจากพื้นที่ด้านบนคอลัมน์ซ้าย และพื้นที่ด้านซ้ายบนแถวบน มันเกิดการ "ทับซ้อน (Overlap)" ตรงบริเวณ `P[i-1][j-1]` ทำให้ถูกบวกเบิ้ลไป 2 ครั้ง เราจึงต้องจับมา "ลบออก 1 ครั้ง" เพื่อให้ยอดรวมถูกต้องเสมอ

**ขั้นที่ 2: การคิวรี (Query) หายอดรวมในกรอบ (r1,c1) ถึง (r2,c2)**
เมื่อเรามีตารางผลรวมสมบูรณ์แบบ `P(i, j)` ครบทุกช่องแล้ว การอยากรู้พื้นที่ใดๆ ทำได้โดยการลบพื้นที่ส่วนเกินออก:
* **Sum = `P[r2][c2] - P[r1-1][c2] - P[r2][c1-1] + P[r1-1][c1-1]`**
  * เริ่มจากใช้สี่เหลี่ยมพื้นที่ใหญ่สุดจนถึงจุดจบคือ `P[r2][c2]`
  * ลบกรอบส่วนเกินด้านบน (ส่วนที่เหนือกรอบที่เราต้องการ) ด้วย `P[r1-1][c2]`
  * ลบกรอบส่วนเกินด้านซ้าย ด้วย `P[r2][c1-1]`
  * เนื่องจากรอยต่อแหว่งมุมซ้ายบน โดนหักลบออกไป 2 รอบเกินเหตุ จึงต้อบวกคืนด้วยพื้นที่ทับซ้อน `P[r1-1][c1-1]`

## 3. อธิบายโค้ดและยกตัวอย่าง Testcase
โปรแกรมภาษา C++ ถูกออกแบบมาโดยพยายามข้ามเรื่อง Base case ที่ต้องจัดการ Index ติดลบ (เช่น `i-1` ตอน `i=0`) ด้วยการเขียนเช็คเงื่อนไข Ternary operator เอาไว้ (ดังที่เห็นในโควตโค้ดบรรทัด 19-21 และ 30-32):
* `int top = (i > 0) ? P[i-1][j] : 0;` (สมมติว่าเป็น 0 หากไม่มีพื้นที่ทางนั้นแล้ว)

**ยกตัวอย่าง Test Case:**
**Input:** 
ขนาดตาราง $N=3, M=5$, และคำถาม $K=7$
```text
1 2 3 4 5
6 6 6 6 6
7 7 3 1 1
```

**Step 1: ประกอบตาราง Prefix Sum (`P[i][j]`)** จะได้ตารางในหน่วยความจำหน้าตาดังนี้:
* แถว 0: `[ 1,  3,  6, 10, 15]`
* แถว 1: `[ 7, 15, 24, 34, 45]`
* แถว 2: `[14, 29, 41, 52, 64]`

**Step 2: จำลองการ Query (7 คำถาม):**
* `0 0 0 0`: ค่าทั้งหมดอยู่ในช่อง `P[0][0]` = `1`
* `0 0 1 1`: เริ่ม 0 ดังนั้นไม่มีให้หักลบ ตอบ `P[1][1]` = `15`
* `1 1 2 1`: เอาพื้นที่ `P[2][1]`(29) หักบน `P[0][1]`(3) หักซ้าย `P[2][0]`(14) คืนมุม `P[0][0]`(1) -> $29 - 3 - 14 + 1$ = `13`
* `1 1 2 3`: `P[2][3]`(52) หักบน `P[0][3]`(10) หักซ้าย `P[2][0]`(14) คืนมุม `P[0][0]`(1)  -> $52 - 10 - 14 + 1$ = `29`
* `1 0 2 2`: `P[2][2]`(41) หักบน `P[0][2]`(6) ซ้ายไม่ต้องเพราะติดขอบ +0  -> $41 - 6$ = `35`
* `0 1 2 2`: `P[2][2]`(41) หักซ้าย `P[2][0]`(14) บนไม่ต้องเพราะติดขอบ +0  -> $41 - 14$ = `27`
* `0 0 2 4`: คลุมทั้งตาราง ตอบช่องสุดท้าย `P[2][4]` = `64`

*(ผลลัพธ์ที่ได้ 1, 15, 13, 29, 35, 27, 64 ตรงกับ Output ที่ต้องการพอดี)*

## 4. Time Complexity
**ความซับซ้อนด้านเวลา (Time Complexity):** **$O(N \times M + K)$**
เหตุผล: การทำงานของโปรแกรมสล็อตนี้แงกเป็น 2 ส่วนหลัก:
1. การเตรียมตาราง 2D Prefix Sum จะวนลูปอ่านและคำนวณสะสมครั้งเดียวเต็มตาราง ใช้เวลา $O(N \times M)$
2. การคำนวณและการตอบคำถาม (Query) จำนวน $K$ คำถาม จะไม่ต้องวนลูปเลย ใช้เพียงสมการบวกลบแค่ 4 ค่า ใช้เวลาเพียง $O(1)$ ต่อคำถาม หรือรวมแล้วใช้ $O(K)$
ดังนั้นเวลาเบ็ดเสร็จสุทธิจะเท่ากับ $O(N \times M + K)$ ถือเป็นวิธีการที่เร็วและรัดกุมมากเมื่อเจอชุดคำถามในปริมาณระดับหมื่นระดับแสน

*(เพิ่มเติม)*
**ความซับซ้อนด้านพื้นที่ (Space Complexity):** **$O(N \times M)$**
เหตุผล: การแก้โจทย์ในวิธีดังกล่าวจำเป็นต้องประกาศตัวแปร Array 2 มิติ คือตาราง Prefix Sum ที่มีขนาดเป๊ะๆ ตามความกว้างคูณยาวของตาราง $A$ ($N$ แถว และ $M$ คอลัมน์) เพื่อเก็บข้อมูลไว้ให้ใช้จนจบการรีเควสชุดสุดท้าย
