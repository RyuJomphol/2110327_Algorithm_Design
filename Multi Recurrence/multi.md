# 🔢 Multi Recurrence (ความสัมพันธ์เวียนเกิดแบบหลายตัวแปร)

## 1. วิเคราะห์โจทย์ Multi Recurrence
โจทย์ปัญหานี้ให้คำนวณหาค่าลำดับที่มีความสัมพันธ์เวียนเกิด (Recurrence Relation) ในรูปแบบที่พจน์ปัจจุบันเกิดจากการนำพจน์ก่อนหน้าหลายๆ พจน์มาบวกกัน โดยไม่ได้บวกพจน์ที่อยู่ติดกันเสมอไป แต่จะบวกพจน์ที่ย้อนหลังไปเป็นระยะ (Offset) ค่าต่างๆ ที่โจทย์กำหนดให้เฉพาะในแต่ละพจน์นั้นๆ

**รูปแบบสมการ:**
$$ R(n) = \begin{cases} 0 & \text{ถ้า } n \le 0 \\ a_n & \text{ถ้า } 0 < n \le k \\ R(n - b_1) + R(n - b_2) + \dots + R(n - b_p) & \text{ถ้า } n > k \end{cases} $$

**คำอธิบาย:**
* $n$ คือ จำนวนพจน์ทั้งหมดที่ต้องการหา
* $k$ คือ จำนวนพจน์ที่เป็น Base case 
* $a_n$ คือ ค่าเริ่มต้นของ $k$ พจน์แรก
* สำหรับพจน์ที่ $n > k$ การหาค่า $R(n)$ จะใช้การบวกค่าของพจน์ย้อนหลังจำนวน $p$ ตัว โดยย้อนหลังไปเป็นระยะ $b_1, b_2, \dots, b_p$ 
* นอกจากนี้ ยังมีการกำหนดให้ผลลัพธ์สุดท้ายทั้งหมดต้องทำ Modulo 32717 เพื่อป้องกันตัวเลขล้น (Integer Overflow) และถ้าพจน์ย้อนหลัง $n - b_j \le 0$ ให้ถือว่ามีค่าเป็น $0$ (ไม่นำมาบวก)

## 2. วิเคราะห์โค้ด Recurrent relation
การประมวลผลความสัมพันธ์เวียนเกิดในข้อนี้ใช้แนวคิด Dynamic Programming (Bottom-Up) เช่นกัน โดยจะสร้างตารางเก็บผลลัพธ์ $R$ เพื่อที่เวลาอ้างอิงถึงพจน์ก่อนหน้า $R(n - b_j)$ จะได้ใช้ค่าจากที่คำนวณและจำไว้แล้วได้เลย โดยไม่ต้องไปเรียกฟังก์ชัน Recursive ให้ซ้ำซ้อน

**สมการที่ใช้ในโค้ด:**
สำหรับแต่ละพจน์ $i > k$ โปรแกรมจะรับค่า $p$ ว่าพจน์นี้ต้องบวกย้อนหลังกี่ตัว จากนั้นจะรับค่าระยะย้อน $b$ มา $p$ ตัว และทำการคัดกรอง:
`ถ้า (i - b) > 0` : 
`   sum = (sum + R[i - b]) % 32717`
แล้วสุดท้ายนำ `sum` ไปเป็นค่าของ `R[i]`

## 3. อธิบายโค้ด
โค้ด C++ นี้มีขั้นตอนการทำงานดังนี้:

1. **ตั้งค่าเริ่มและการรับข้อมูลเบื้องต้น:**
   * สั่งตั้งค่า I/O `ios::sync_with_stdio(false); cin.tie(nullptr);` เพื่อการรับข้อมูลที่รวดเร็ว
   * รับค่าจำนวนพจน์ทั้งหมด `n` และจำนวนค่าตั้งต้น `k`
   * สร้างเวกเตอร์ `vector<int> R(n + 1)` อาเรย์ 1 มิติ สำหรับเก็บค่าลำดับตั้งแต่พจน์ที่ $1$ ถึง $n$
   * กำหนดคงที่เอาเศษ `mod_num = 32717`

2. **รับค่าฐาน (Base cases):**
   * วนลูปรับค่าฐานใส่ไว้ใน `R[1]` ไปจนถึง `R[k]` และจัดการทำ modulo `mod_num` ไว้ล่วงหน้า

3. **วนลูปคำนวณพจน์ที่เหลือ (Bottom-Up Calculation):**
   * ลูปนอกทำงานตั้งแต่พจน์ที่ $i = k + 1$ ถึง $n$
   * ในแต่ละรอบ $i$ ให้รับค่า $p$ (จำนวนตัวที่ต้องย้อนไปหยิบมาบวก) 
   * ตั้งค่า `sum = 0` 
   * สร้างลูปข้างใน วนรับค่าเป้าหมายคือระยะย้อน $b$ จำนวน $p$ รอบ 
   * ตรวจสอบว่า `previous_index = i - b` มากกว่า 0 หรือไม่ (ตามเงื่อนไข $R(n) = 0$ เมื่อ $n \le 0$)
   * หากเข้าเงื่อนไข จะนำค่าในตาราง `R[previous_index]` มาสะสมใส่ใน `sum` แล้ว Modulo ทันที
   * เมื่อวนสะสมครบทั้ง $p$ ตัว ก็จะเก็บค่า `sum` ไว้ที่ `R[i]`

4. **แสดงผลลัพธ์:**
   * ลูปเพื่อปริ้นค่าที่อยู่ใน Array เริ่มตั้งแต่ตำแหน่งแรก `R[1]` จนถึง `R[n]` ออกมาตามลำดับ

## 4. Time Complexity
**ความซับซ้อนด้านเวลา (Time Complexity):** **$O(n + \sum p)$** หรือ **$O(n \times p_{max})$**
เหตุผล: ลูปหลักทำงานทั้งหมด $n - k$ รอบ (ตีง่ายๆ คือ $O(n)$) และในแต่ละพจน์ที่ $i$ จะมีการวนลูปรับค่าย้อนหลังอีก $p_i$ รอบ ดังนั้นจำนวน Operation ทั้งหมดของการวนลูปจะเป็นการรวมกันของค่า $p$ ในทุกๆ สเต็ป ($p_{k+1} + p_{k+2} + \dots + p_n$) ซึ่งถ้าเรามองแบบขอบเขตบนสุด (Worst Case) ก็จะไม่เกิน **$O(n \times p_{max})$** 

*(เพิ่มเติม)*
**ความซับซ้อนด้านพื้นที่ (Space Complexity):** **$O(n)$**
เหตุผล: การแก้โจทย์ข้อนี้มีการจอง Array `vector<int> R(n + 1)` ขนาด $n+1$ เพื่อเก็บพจน์ทุกพจน์เอาไว้ใช้ในกรณีที่ต้องเรียกค่าย้อนหลังแบบข้ามไปมา และตัวโจทย์บังคับให้ปริ้นพจน์ทั้งหมด (ตั้งแต่ 1 ถึง $n$) ในตอนท้าย การเก็บข้อมูลทั้งหมดไว้จึงเหมาะและใช้พื้นที่แปรผันตรงกับขนาดของ $n$ ครับ
