# 🔺 Number Triangles (สามเหลี่ยมตัวเลข)

## 1. วิเคราะห์โจทย์ Number Triangle
โจทย์กำหนดโครงสร้างสามเหลี่ยมตัวเลขขนาด $N$ ระดับ (Level) โดยระดับที่ 1 (บนสุด) จะมีตัวเลข 1 ตัว, ระดับที่ $i$ จะมีตัวเลข $i$ ตัว 
เป้าหมายของปัญหาคือการหาเส้นทางเดินจาก "จุดยอด (บนสุด)" ลงมายัง "ฐาน (ล่างสุด)" โดยให้ **"ผลรวมตัวเลขระหว่างทางมีค่ามากที่สุด"**
กฎการเดินทางดังนี้:
1. การเดินทางต้องเริ่มจากแถวบนสุด (ระดับ 1) และจบที่แถวล่างสุดเสมอ
2. ในการก้าวลงระดับถัดไป หากเรายืนอยู่ที่ตัวเลขลำดับที่ $k$ ในชั้นที่ $L$ เราจะสามารถก้าวลงไปได้แค่ 2 ทางเลือกเท่านั้น คือ:
   * **เส้นทางทะแยงซ้าย:** ลงไปยังตัวเลขลำดับที่ $k$ ของชั้น $L+1$ 
   * **เส้นทางทะแยงขวา:** ลงไปยังตัวเลขลำดับที่ $k+1$ ของชั้น $L+1$

ปัญหานี้คือแบบฉบับมาตรฐานของการใช้เทคนิค **Dynamic Programming** เนื่องจากการเดินจากยอดลงมาฐาน หากใช้วิธีไล่ไปทุกเส้นทางแบบ Recursive ธรรมดาจะเกิดการทำซ้ำ (Overlapping Subproblems) อย่างมหาศาล ($2^{N-1}$ เส้นทาง)

## 2. วิเคราะห์ที่มาสมการ Recurrence Relation
ในวิธีการทำ Dynamic Programming ของโจทย์ข้อนี้ **การเดินย้อนกลับจากฐานขึ้นไปหายอด (Bottom-Up)** เป็นวิธีที่ฉลาดและเขียนโค้ดได้ง่ายที่สุด เพราะเราไม่ต้องคอยคำนึงถึงขอบ (Boundary) สองข้างว่ามาจากต้นทางไหนเหมือนการเดินจากบนลงล่าง

สมมติให้ `triangle[i][j]` ของเดิมคือตัวเลขที่ตำแหน่ง $j$ บนชั้นที่ $i$ 
หากเรายืนอยู่ที่ตำแหน่งนี้ และมองลงไปข้างล่าง เราจะมีทางเลือกให้เดินลงคือ `triangle[i+1][j]` (ซ้าย) กับ `triangle[i+1][j+1]` (ขวา) 
การจะตัดสินใจเลือกเดินทางไหน ก็แค่ดูว่าข้างล่างสองทางนั้น **"ทางไหนมีผลรวมสะสมที่มากกว่ากัน"** ก็ให้บวกค่าตัวมันเองเข้ากับทางนั้น เพื่อเก็บเป็นผลรวมสะสมสำหรับให้พวกชั้นบนๆ ได้ประเมินผลต่อไป

**สมการ Recurrence Relation:**
`triangle[i][j] += max(triangle[i+1][j], triangle[i+1][j+1])`
*(ความหมายคือ: ค่าความคุ้มค่าที่ยืนอยู่จุดนี้ = ตัวเลขประจำจุดนี้ + การเลือกสิ่งที่รวมคะแนนได้เยอะกว่าในก้าวถัดไป)*

**Base Cases:**
ชั้นที่ล่างสุด (ระดับ $N$) ถือเป็นขอบเขตสุดท้ายที่ไม่มีก้าวถัดไปให้เลือกแล้ว ค่าเริ่มต้นของมันคือตัวเลขของมันเองโดยตรง

## 3. อธิบายโค้ดและยกตัวอย่าง Testcase
**การทำงานของโค้ด:**
1. รับค่าจำนวนแถว `N`
2. สร้าง 2D Vector ทรงสามเหลี่ยม `vector<vector<int>> triangle(N)`
3. ใช้ลูปคู่เพื่อรับค่าตัวเลขทั้งหมดใส่เข้าไปใน `triangle` โดยที่แถวที่ $i$ จะมีขนาดความกว้างตามชั้น `i + 1` (โค้ดใช้ `.resize(i+1)`)
4. **กระบวนการ DP แบบ Bottom-Up:**
   * เริ่มวนลูปแถว `i` จากชั้นรองสุดท้ายขึ้นมาหาชั้นบนสุด (`i = N - 2` ไล่ลงไปถึง `0`)
   * วนลำดับจุดหมาย `j` ทุกตัวในแถว `i`
   * ทำการนำตัวเลขลูกน้องที่อยู่ข้างใต้ ได้แก่ตำแหน่งตรงๆ `[i+1][j]` (เปรียบเสมือนซ้าย) และตัวถัดไป `[i+1][j+1]` (เปรียบเสมือนขวา) มาเทียบหาค่า `max` 
   * นำค่า `max` ดังกล่าวไปบวกทับเข้ากับตัวโปรแกรมที่จุด `triangle[i][j]` อย่างเดิม เพื่อให้จุดนี้กลายเป็นยอดรวมสูงสุดนับจากจุดมันลงไปถึงเส้นชัยฐานด้านล่าง
5. พอลูปจบการทำงานครบทุกแถวไปจนถึง `i = 0` คำตอบคะแนนรวมสุดท้ายที่ประเมินเส้นทางได้คุ้มที่สุดจะมารวมศูนย์กันอยู่ที่จุดยอดสุด คือปริ้นท์ตัวแปร `triangle[0][0]` เป็นคำตอบจบ 

**ยกตัวอย่าง Test Case:**
**Input:** 
ขนาด $N=5$
```text
7
3 8
8 1 0
2 7 4 4
4 5 2 6 5
```

**การคาดการณ์ยอด DP (เทียบจากล่างขึ้นบน):**
* **เริ่มต้น:** ฐานของสามเหลี่ยม (แถวที่ 4 ใน index 0)
  `[4, 5, 2, 6, 5]`
* **อัปเดตแถวที่ 3:**
  * ตำแหน่งที่ 0 `(2)`: ข้างล่างคือ 4 กับ 5 -> ค่า max คือ `5` -> ยอดรวมเป็น `2 + 5 = 7`
  * ตำแหน่งที่ 1 `(7)`: ข้างล่างคือ 5 กับ 2 -> ค่า max คือ `5` -> ยอดรวมเป็น `7 + 5 = 12`
  * ตำแหน่งที่ 2 `(4)`: ข้างล่างคือ 2 กับ 6 -> ค่า max คือ `6` -> ยอดรวมเป็น `4 + 6 = 10`
  * ตำแหน่งที่ 3 `(4)`: ข้างล่างคือ 6 กับ 5 -> ค่า max คือ `6` -> ยอดรวมเป็น `4 + 6 = 10`
  *(แถวที่ 3 ตอนนี้คือ `[7, 12, 10, 10]`)*
* **อัปเดตแถวที่ 2:**
  * ตำแหน่งที่ 0 `(8)`: เลือก `max(7, 12) = 12` -> รวมยอดได้ `8 + 12 = 20`
  * ตำแหน่งที่ 1 `(1)`: เลือก `max(12, 10) = 12` -> รวมยอดได้ `1 + 12 = 13`
  * ตำแหน่งที่ 2 `(0)`: เลือก `max(10, 10) = 10` -> รวมยอดได้ `0 + 10 = 10`
  *(แถวที่ 2 ตอนนี้คือ `[20, 13, 10]`)*
* **อัปเดตแถวที่ 1:**
  * ตำแหน่งที่ 0 `(3)`: เลือก `max(20, 13) = 20` -> รวมยอดได้ `3 + 20 = 23`
  * ตำแหน่งที่ 1 `(8)`: เลือก `max(13, 10) = 13` -> รวมยอดได้ `8 + 13 = 21`
  *(แถวที่ 1 ตอนนี้คือ `[23, 21]`)*
* **อัปเดตแถวที่ 0 (จุดยอด):**
  * ตำแหน่งที่ 0 `(7)`: เลือกลูกน้องระหว่าง `23` กับ `21` -> ค่า `max(23, 21) = 23` 
  * ปิดจ๊อบรวมยอดสุดท้ายเป็น `7 + 23 = 30` 

ผลลัพธ์ที่ขึ้นไปกองรวมอยู่ที่จุดยอดคือ `30` ซึ่งตรงกับเส้นทางจากโจทย์ $7 \to 3 \to 8 \to 7 \to 5$ ที่ได้ Output `30` 

## 4. Time Complexity
**ความซับซ้อนด้านเวลา (Time Complexity):** **$O(N^2)$**
เหตุผล: การแก้โจทย์ในวิธีดังกล่าว เราไม่ได้ทำงานเป็น Tree $O(2^N)$ แต่ใช้ Nested loops วนตั้งแต่ชั้นรองล่างสุดขึ้นมาเรื่อยๆ และในแต่ละรอบ `i` จะถูกวนแค่ตามจำนวนสมาชิกที่มีในชั้นนั้น `j` (ประมาณ $i$ ครั้ง) เมื่อนำจำนวนรอบทั้งหมดมารวมกันก็คือ $1 + 2 + 3 + ... + N = \frac{N(N+1)}{2}$ ทำให้สรุปออกมาได้เป็น **$O(N^2)$** ซึ่งเป็นเวลาที่มีประสิทธิภาพสูงสุดในการสำรวจปัญหาโครงสร้างนี้

*(เพิ่มเติม)*
**ความซับซ้อนด้านพื้นที่ (Space Complexity):** **$O(N^2)$**
เหตุผล: โปรแกรมสร้างเวกเตอร์ความจำแบบสามเหลี่ยม 2 มิติ คือ `vector<vector<int>> triangle(N)` ตามขนาด $N$ ชั้น โดยแต่ละชั้นใช้ที่เก็บข้อมูลตามลำดับเลขคณิต ทำให้ใช้พื้นที่แปรผันเปรียบเทียบกับขนาดทั้งหมดเป็น $O(N^2)$ (ข้อสังเกต: โค้ดนี้ทำแบบการบวกทับที่เดิม (In-place modification) จึงเป็นการใช้ตัวแปรของ input ต้นทางไปจัดเก็บ DP โดยไม่ต้องสร้างตาราง 2D เปลืองเนื้อที่ข้างนอกเพิ่มอีก)
