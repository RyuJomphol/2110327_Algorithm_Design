# Ones

## 1. วิเคราะห์โจทย์
โจทย์: ให้จำนวนเต็มบวก `n` ต้องการเขียนค่า `n` โดยใช้ตัวเลขชนิดพิเศษที่เป็นตัวเลขทั้งหมดประกอบด้วยหลัก `1` เท่านั้น (เช่น 1, 11, 111, 1111, ...) ทั้งบวกและลบได้ (เช่น เราอาจใช้ 111 + 11 - 1 = 121) เราต้องการหาจำนวนตัวอักษร `'1'` ขั้นต่ำที่ต้องใช้

แนวทาง: Greedy + Recurrence + Memoization
- กำหนด q[k] = จำนวนเต็มที่มี `k` หลักเป็น '1' (q[1]=1, q[2]=11, q[3]=111, ...)
- สำหรับระดับ `k` ใหญ่สุดที่ q[k] ≥ n ให้ลองใช้จำนวนเต็ม q[k] เป็นตัวแบ่ง:
  - ใช้ `cnt = n / q[k]` ชิ้นของ q[k] (แต่ละชิ้นใช้ `k` ตัวอักษร '1') แล้วแก้ปัญหาที่เหลือ `rem = n % q[k]` ด้วย q[k-1]
  - หรือเลือกใช้หนึ่งชิ้นเพิ่ม (cnt+1) ของ q[k] แล้วลบส่วนที่เกิน (q[k] - rem) โดยแก้ปัญหา q[k] - rem ด้วย q[k-1]
- เลือกแบบที่ให้จำนวน `'1'` น้อยกว่า และเก็บผลใน memo เพื่อลดการคำนวณซ้ำ

เหตุผล: การใช้บล็อก q[k] จำนวนเต็มขั้นสูงสุดช่วยลดจำนวนหลัก `'1'` ได้มาก (แต่บางครั้งการใช้ชิ้นเกินและลบส่วนเล็ก ๆ ด้วยบล็อกเล็กกว่าให้ต้นทุนรวมต่ำกว่า) — การลองทั้งสองเป็นกรณีครอบคลุมและ recursion/เมโมช่วยให้ค้นหาค่าต่ำสุดได้

## 2. วิเคราะห์โค้ด
- สร้าง `q[1..12]` เป็น 1, 11, 111, ... (โค้ดสร้างจน `i=12`)
- หา `start_k` คือ index แรกที่ `q[start_k] >= n`
- ฟังก์ชัน `solve(n, k)` ทำงานดังนี้:
  - ถ้า `k == 1` คืน `n` (เพราะ q[1]=1 ต้องใช้ `n` ตัว '1' เพื่อเขียน `n`)
  - ใช้ memoization (map) เก็บคู่ `(n,k)` เพื่อไม่ให้คำนวณซ้ำ
  - คำนวณ `cnt = n / q[k]` และ `rem = n % q[k]`
  - กรณี 1: ใช้ `cnt` ชิ้นของ q[k] แล้วแก้ `rem` ด้วย `k-1` → cost = `cnt * k + solve(rem, k-1)`
  - กรณี 2: ใช้ `cnt+1` ชิ้นของ q[k] แล้วลบส่วนเกิน `q[k]-rem` ด้วย `k-1` → cost = `(cnt+1) * k + solve(q[k]-rem, k-1)`
  - คืนค่า min ของสองกรณีและเก็บใน `memo`

โค้ดพิมพ์ `solve(n, start_k)` เป็นผลลัพธ์

## 3. ตัวอย่าง Test Case (ตามที่ให้)
Input:
```
121
```
Output:
```
6
```

อธิบายขั้นตอนการคำนวณ (trace เพิ่มเติม):
- q: q1=1, q2=11, q3=111, q4=1111, …
- หา start_k ที่ q[k] ≥ 121 → q3=111 <121, q4=1111 ≥121 ⇒ start_k = 4

เรียก `solve(121,4)`:
- cnt = 121 / 1111 = 0, rem = 121
- ตัวเลือก:
  1) cost1 = 0*4 + solve(121,3) = solve(121,3)
  2) cost2 = 1*4 + solve(1111-121=990, 3) = 4 + solve(990,3)
- เลือก cost1 เพราะเล็กกว่า (จะได้ 6)

คำนวณ `solve(121,3)`:
- q3=111 → cnt = 121 / 111 = 1, rem = 10
- option1 = 1*3 + solve(10,2) = 3 + solve(10,2)
- option2 = 2*3 + solve(111-10=101,2) = 6 + solve(101,2)
- เลือก option1

คำนวณ `solve(10,2)`:
- q2=11 → cnt = 10 / 11 = 0, rem = 10
- option1 = 0*2 + solve(10,1) = solve(10,1) = 10
- option2 = 1*2 + solve(11-10=1,1) = 2 + 1 = 3
- เลือก option2 → solve(10,2) = 3

กลับขึ้นไป: solve(121,3) = 3 + 3 = 6 → solve(121,4) = 6 → output 6

ตัวอย่าง decomposition ที่ให้ผล 6 ตัว '1':
```
111 (3 ones) + 11 (2 ones) - 1 (1 one) = 121
```
รวมตัว '1' = 3 + 2 + 1 = 6

ASCII trace ของการเลือก (ย่อ):

Start: n=121, use q3=111 once -> remaining 10
Handle 10 using q2 (11): either 10*'1' (cost 10) or 11 - 1 (cost 2 + 1 =3)
Choose 11 - 1 → costs 3 -> combine with earlier 3 → total 6

## 4. Big O / Big Theta
- ปริมาณสถานะ (n,k) ที่ `solve` อาจเทียบได้กับค่า `n` ที่ปรากฏใน recursion และระดับ `k` (k ≈ number of digits of n, ที่โค้ดจำกัดไว้ ≤12)
- แต่ละสถานะถูกคำนวณเพียงครั้งเดียว (memo)
- ในเชิงทฤษฎี worst-case จำนวนสถานะ ≈ O(n * k) จึงเวลาโดยรวม O(n * k)
- ในโค้ดจริง `k` ถูกจำกัดที่ 12 (q สร้างจน i=12) ดังนั้นเวลาเป็นเชิงปฏิบัติ Θ(n) สำหรับขนาด `n` ที่รองรับ

สรุปโดยย่อ:
- Time (worst) = O(n * k) (โดย k = number of q-levels used). เมื่อ k bounded (โค้ดใช้ k ≤ 12) → Time ≈ Θ(n)
- Space = O(number_of_memo_states) ≤ O(n * k) (แต่ในปฏิบัติ small), plus recursion depth O(k)
