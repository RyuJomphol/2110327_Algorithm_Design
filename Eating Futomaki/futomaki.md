# 🍣 Eating Futomaki (การแบ่งฟุโตะมากิ)

## 1. วิเคราะห์โจทย์ Eating Futomaki
นายแด้มีฟุโตะมากิที่ถูกหั่นมาแล้ว $N$ ชิ้น แต่ละชิ้นมีความอร่อยไม่เท่ากัน เก็บอยู่ในอาเรย์ $A[1..N]$
กติกาในการแบ่งกินกับเพื่อน (นายชิน) คือ:
- นายแด้ต้องหยิบฟุโตะมากิออกมาครั้งละ **2 ชิ้น** จากส่วนหัว (ซ้ายสุด) หรือ ส่วนท้าย (ขวาสุด) ของฟุโตะมากิที่เหลืออยู่เท่านั้น
- จาก 2 ชิ้นที่หยิบมา นายแด้จะเลือกกินชิ้นที่ "อร่อยที่สุด" 1 ชิ้น และอีก 1 ชิ้นที่เหลือยกให้นายชิน
- ทำแบบนี้ไปเรื่อยๆ จนกว่าฟุโตะมากิจะหมด
เป้าหมายคือ นายแด้ต้องการหาวิธีหยิบที่ทำให้ **"ผลรวมความอร่อยของชิ้นที่ตัวเองได้กิน มีค่ามากที่สุด"**

ลักษณะการหยิบของจากหัวท้ายทีละ 2 ชิ้น เราสามารถแบ่งกรณีการหยิบของนายแด้ในแต่ละรอบได้เพียง 3 รูปแบบ คือ:
1. หยิบจากทางซ้ายทั้ง 2 ชิ้น (ซ้ายสุด และ รองซ้ายสุด)
2. หยิบจากทางขวาทั้ง 2 ชิ้น (ขวาสุด และ รองขวาสุด)
3. หยิบจากทางซ้าย 1 ชิ้น และทางขวา 1 ชิ้น (ซ้ายสุด และ ขวาสุด)

ปัญหานี้จึงสามารถแก้ได้ด้วย **Dynamic Programming (Top-Down แนว Divide and Conquer)** เพื่อจำลองการตัดส่วนหัวท้ายขยับบีบช่วงเข้าไปเรื่อยๆ

## 2. วิเคราะห์ที่มาสมการ Recurrence Relation
ให้ `solve(L, R)` หมายถึง ผลรวมความอร่อยมากที่สุดที่นายแด้จะได้รับ เมื่อเหลือฟุโตะมากิตั้งแต่ตำแหน่งที่ $L$ ถึง $R$
รูปแบบการตัดสินใจจาก 3 ทางเลือก จะได้สมการดังนี้:

**Recurrence Relation:**
`solve(L, R) = max ก้อนที่ดีที่สุดจาก 3 ทางเลือก`
* **ทางเลือก 1 (หยิบซ้าย 2 ชิ้น):** นายแด้กิน `max(A[L], A[L+1])` และช่วงที่เหลือถูกบีบเป็น `solve(L+2, R)`
* **ทางเลือก 2 (หยิบขวา 2 ชิ้น):** นายแด้กิน `max(A[R], A[R-1])` และช่วงที่เหลือถูกบีบเป็น `solve(L, R-2)`
* **ทางเลือก 3 (หยิบซ้าย 1 ชิ้น ขวา 1 ชิ้น):** นายแด้กิน `max(A[L], A[R])` และช่วงที่เหลือถูกบีบทั้ง 2 ด้านเป็น `solve(L+1, R-1)`

**Base Cases (กรณีฐานเริ่มต้น):**
* หาก `L >= R` หมายความว่าเหลือชิ้นฟุโตะมากิน้อยกว่า 2 ชิ้น (ซึ่งผิดปกติในโจทย์ หรือถูกกินหมดพอดี) ให้คืนค่าผลรวมเป็น `0` เพราะหยิบเป็นคู่ไม่ได้แล้ว

## 3. อธิบายโค้ดและยกตัวอย่าง Testcase
**การทำงานของโค้ด:**
1. โปรแกรมประกาศอาเรย์ `A[MAXN]` และตารางจดจำ `memo[MAXN][MAXN]` ขนาด $5005 \times 5005$ รับรองจำนวนชิ้นที่เยอะมากๆ
2. ใช้ฟังก์ชัน `memset(memo, -1, sizeof(memo))` เพื่อตั้งค่าตารางจำผลลัพธ์ทุกช่องเป็น `-1` ก่อนเริ่มงาน (ค่าติดลบหมายถึงยังไม่ได้คำนวณ)
3. ภายในฟังก์ชัน `solve(L, R)` เมื่อรับพิกัดขอบซ้ายขวาเข้ามา จะเช็คก่อนว่ามีในสมุดจด (memo) ไหม ถ้ามี `!= -1` คืนค่าที่จดไว้ได้เลย (ลดเวลาการทำงานซ้ำซ้อน)
4. ถ้าไม่เคยคำนวณ จะเข้าสู่กระบวนการเทียบ 3 ทางเลือก (ซ้ายคู่รวด, ขวาคู่รวด, ซ้ายขวาผสมกัน) 
5. สุดท้ายจะคืนค่าที่มากที่สุดจากการหา `max` ของทั้ง 3 ทางเลือกทับลงใน `memo[L][R]` เพื่อจดจำไว้ใช้งานต่อ
6. เริ่มรันโปรแกรมจากกล่องใหญ่สุด (กล่องตั้งต้นที่ยังไม่ถูกกิน) คือ `solve(0, n - 1)`

**ยกตัวอย่าง Testcase:**
**Input:** `6` ชิ้น ค่าความอร่อยคือ `9 8 7 3 2 1`
**วิเคราะห์เส้นทางการหยิบ (Trace):**
ฟังก์ชันเริ่มแบบเต็มสตริงที่ขอบซ้าย `L = 0` (ค่าคือ 9) ขอบขวา `R = 5` (ค่าคือ 1)
* **ก้าวแรก:** เลือกหยิบแบบ "ซ้าย 1 ขวา 1" คือเลข `[9, 1]` ค่าย่อยที่ได้กินคือ `max(9, 1) = 9` 
  * แถวที่เหลืออยู่จะขยับกรอบเข้ามากลายเป็น `[8, 7, 3, 2]`
* **ก้าวสอง:** จากอาเรย์ `[8, 7, 3, 2]` เลือกลงแบบ "ซ้าย 1 ขวา 1" อีกครั้ง คือเลข `[8, 2]` ค่าย่อยที่ได้กินคือ `max(8, 2) = 8`
  * แถวที่เหลืออยู่ขยับกรอบเข้ามาสุดๆ กลายเป็น `[7, 3]`
* **ก้าวสาม:** จากอาเรย์ `[7, 3]` ไม่ว่าหยิบซ้ายขวาหรืออย่างไรก็ได้ไส้คู่นี้ไปกินอยู่ดี คือเลข `[7, 3]` ค่าย่อยที่ได้กินคือ `max(7, 3) = 7`
  * แถวหมดแล้ว จบการทำงาน

รวมยอดความอร่อยที่นายแด้เก็บได้มากที่สุดคือ `9 + 8 + 7 = 24` ตรงกับ Output พอดี

## 4. Time Complexity
**ความซับซ้อนด้านเวลา (Time Complexity):** **$O(N^2)$**
เหตุผล: การแก้โจทย์ด้วยวิธี Top-Down DP ด้วย Memoization จะรับประกันว่าเราคำนวณคู่พิกัด $(L, R)$ แต่ละรูปแบบเพียงแค่ 1 ครั้งเท่านั้น ซึ่งคู่ $(L, R)$ ที่เป็นไปได้ทั้งหมดภายใต้ความยาว $N$ จะมีประมาณ $\frac{N(N-1)}{2}$ รูปแบบ และในแต่ละรูปแบบเราทำการบวกลบเปรียบเทียบแค่ 3 ทางเลือก ($O(1)$) ระยะเวลาทำงานโดยรวมของปัญหาจึงตกลงที่ $O(N^2)$

*(เพิ่มเติม)*
**ความซับซ้อนด้านพื้นที่ (Space Complexity):** **$O(N^2)$**
เหตุผล: เพราะโปรแกรมต้องกาง Array 2 มิติ คือตาราง `memo[MAXN][MAXN]` เพื่อให้ครอบคลุมการเซฟคำตอบของคู่พิกัดขอบซ้าย `L` และขอบขวา `R` ได้ครบทุกแบบ จึงต้องกินบรรจุความจุเป็นชิ้นเป็นอันตาม $O(N^2)$ ควบคู่กับการกิน Call stack ในหน่วยความจำกรณีการเรียกฟังก์ชันซ้อนกันลึกๆ ของ Recursion อีกเล็กน้อย ($O(N)$)
