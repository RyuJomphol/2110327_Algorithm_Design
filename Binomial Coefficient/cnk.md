# 📚 Binomial Coefficient (สัมประสิทธิ์ทวินาม)

## 1. วิเคราะห์โจทย์ Binomial Coefficient
สัมประสิทธิ์ทวินาม (Binomial Coefficient) มักจะเขียนแทนด้วยสัญลักษณ์ **C(n, k)** หรือ **nCr** (อ่านว่า "n choose k") ซึ่งหมายถึงจำนวนวิธีในการเลือกสิ่งของ **k** ชิ้น ออกจากสิ่งของทั้งหมด **n** ชิ้น โดย**ไม่คำนึงถึงลำดับ**ของสิ่งของที่ถูกเลือก
ในทางคณิตศาสตร์สามารถคำนวณได้จากสูตร:
`C(n, k) = n! / (k! * (n - k)!)`

แต่การคำนวณด้วย Factorial โดยตรงในการเขียนโปรแกรม มักจะเกิดปัญหาตัวเลขล้น (Integer Overflow) ได้ง่ายเพราะแฟกทอเรียลมีค่าเติบโตเร็วมาก จึงนิยมใช้เทคนิค Dynamic Programming ร่วมกับความสัมพันธ์เวียนเกิด (Recurrence Relation) ในการแก้ปัญหา เพื่อเลี่ยงการคำนวณแฟกทอเรียลตรงๆ และช่วยลดปัญหาการคำนวณซ้ำซ้อน

## 2. วิเคราะห์โค้ด Recurrent Relation (ความสัมพันธ์เวียนเกิด)
การคำนวณแบบ Dynamic Programming จำลองวิธีมาจากสามเหลี่ยมพาสคัล (Pascal's Triangle) ซึ่งมีความสัมพันธ์เวียนเกิดดังนี้:

**Recurrence Relation:**
`C(n, k) = C(n - 1, k - 1) + C(n - 1, k)`

**ความหมายของความสัมพันธ์นี้:**
* **C(n-1, k-1):** กรณีที่เราหยิบของชิ้นที่ n มาด้วย ทำให้เราเหลือของให้เลือกอีกแค่ k-1 ชิ้น จากทั้งหมด n-1 ชิ้นที่หลงเหลืออยู่
* **C(n-1, k):** กรณีที่เรา**ไม่หยิบ**ของชิ้นที่ n เราจึงยังคงต้องเลือกสิ่งของให้ครบ k ชิ้น จาก n-1 ชิ้นที่เหลืออยู่ข้างหน้า
จำนวนวิธีทั้งหมดจึงคือผลบวกของทั้ง 2 กรณีนี้รวมกัน

**Base Cases (กรณีฐานที่หยุดการเวียนเกิด):**
`C(n, 0) = 1` และ `C(n, n) = 1`
* **C(n, 0):** หากเราออกแบบให้เลือกหยิบของ 0 ชิ้นจาก n ชิ้น มี 1 วิธีเท่านั้น คือ "ไม่หยิบเลยสักชิ้น"
* **C(n, n):** หากเราเลือกหยิบของ n ชิ้นจากของทั้งหมด n ชิ้น จะมีแค่ 1 วิธีเท่านั้น คือ "หยิบทั้งหมด"

## 3. อธิบายโค้ด
โค้ดภาษา C++ นี้ใช้วิธี **Dynamic Programming** แบบ Bottom-Up (Tabulation) เพื่อคำนวณค่า C(n, k) อย่างมีประสิทธิภาพ โดยมีกระบวนการดังนี้:

1. **รับค่าตัวแปร:** โปรแกรมเริ่มจากรับ input จำนวนข้อมูลทั้งหมด `n` และชิ้นของที่ต้องเลือก `k`
2. **สร้าง DP Table:** อาเรย์ 2 มิติ `vector<vector<int>> dp(n + 1, vector<int>(n + 1))` ขนาด (n+1) x (n+1) ถูกสร้างขึ้นมาเพื่อเก็บผลลัพธ์ย่อยๆ ไว้ (แทนตารางสามเหลี่ยมพาสคัล)
3. **การทำงานของลูป (Nested Loops):**
   * ลูปนอก `i` วิ่งตั้งแต่ 0 จนถึง `n` เป็นตัวแทนระดับชั้น (จำนวนสิ่งของที่เรามี)
   * ลูปใน `j` วิ่งตั้งแต่ 0 จนถึง `i` เป็นตัวแทนชิ้นของที่ต้องการหยิบ (เราไม่สามารถหยิบ `j` ชิ้นให้เกินชิ้นของที่มี `i` ชิ้นได้)
4. **กำหนดค่ากรณีฐาน (Base Cases):** 
   * โปรแกรมเช็คเงื่อนไข `if (j == 0 || j == i)` ซึ่งก็คือกรณีที่เลือกของ 0 ชิ้น หรือต้องการหยิบทั้งหมดพอดี ในกรณีนี้ ค่าที่เก็บในตารางจะเป็น 1 เสมอ (`dp[i][j] = 1`)
5. **การคำนวณค่าทั่วไปเมื่อไม่ใช่กรณีฐาน:**
   * โปรแกรมนิยามสมการ Recurrence Relation เป็นโค้ด: `dp[i][j] = dp[i - 1][j - 1] + dp[i - 1][j]`
   * หมายถึงค่าที่ช่องปัจจุบัน ได้มาจาก "ช่องแถวบนเยื้องซ้าย (`[i-1][j-1]`)" บวกกับ "ช่องแถวบนตรงๆ (`[i-1][j]`)"
6. **แสดงผลลัพธ์:** หลังจากการวนลูปคำนวณตารางจนครบหมด ค่าคำตอบสุดท้ายของโปรแกรมที่เราต้องการคือ `dp[n][k]` เราจึงพิมพ์ค่านั้นออกมา

## 4. Time Complexity
**ความซับซ้อนด้านเวลา (Time Complexity):** **O(n²)** 
เหตุผล: การใช้วงวนลูปซ้อนกันสองชั้น (Nested Loops) โดยลูปแรก `i` ทำงานรอบที่ 0 ถึง n และลูปใน `j` วนรอบขึ้นอยู่กับค่า `i` (ทั้งหมดประมาณ `1 + 2 + 3 + ... + (n+1)` ครั้ง) ซึ่งอนุกรมเลขคณิตนี้ทำให้ฟังก์ชันอัตราการเติบโตจะตกอยู่ที่ **O(n²)** ถือว่ามีประสิทธิภาพและรวดเร็วกว่าการทำ Recursive ธรรมดาที่มักจะมีอัตราการเติบโตที่ O(2ⁿ)

**ความซับซ้อนด้านพื้นที่ (Space Complexity):** **O(n²)**
เหตุผล: เพราะเราทำการสร้างอาเรย์ 2 มิติขนาด (n+1) x (n+1) อย่างไรก็ตาม เราสามารถลด Space Complexity ตรงนี้ให้เหลือเพื่อแค่ **O(n)** ได้ถ้าเปลี่ยนไปเก็บค่าตารางเป็นอาเรย์ 1 มิติ (เพราะการหาค่าแถวใหม่ ใช้ค่าจากแถวที่เรียนไปก่อนหน้าเท่านั้น)
