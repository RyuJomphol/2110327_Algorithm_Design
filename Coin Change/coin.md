# Coin Change

## 1. วิเคราะห์โจทย์ Coin Change

เราได้รับชุดของหน่วยเงิน (เหรียญ/ธนบัตร) แต่ละหน่วยมีค่าต่างกัน เช่น
`1`, `2`, `5`, `10`, …  
เมื่อให้จำนวนเงิน `M` ต้องใช้หน่วยเหล่านี้รวมกันให้ได้ค่าเท่ากับ `M`  
โดย **ใช้จำนวนชิ้น (เหรียญ+ธนบัตร) น้อยที่สุด**

ตราบใดที่ค่าหน่วยสามารถใช้ซ้ำได้ไม่จำกัด และมีค่าบวก ปัญหาจะเป็น
เวอร์ชัน "Coin Change" ที่รู้จักกันดี  
(ต่างจาก greedy ที่ไม่แน่นอนเมื่อระบบสกุลเงินกำหนดเอง)

ตัวอย่างจากคำอธิบาย: 
หน่วย `{5,4,1}` สำหรับ `M=8`  
การเลือกแบบ greedy จะได้ `5+1+1+1` (4 ชิ้น)  
แต่ optimum คือ `4+4` (2 ชิ้น) ซึ่งแสดงว่า greedy ล้มเหลว

## 2. วิเคราะห์ที่มาสมการ Recurrence Relation

กำหนด `dp[x]` = จำนวนเหรียญน้อยที่สุดที่รวมเป็นมูลค่า `x`  
ฐาน: `dp[0] = 0` (ไม่ใช้เหรียญ)

เมื่อเราต้องการคำนวณ `dp[x]` สำหรับ `x>0`  
เราสามารถพิจารณาวิธีสุดท้ายที่เพิ่มเข้ามาคือเหรียญชนิด `c` ใดหนึ่ง
ดังนั้น
```
for each coin c:
    if x >= c:
        dp[x] = min(dp[x], dp[x - c] + 1)
```
รูปแบบนี้เรียกว่า unbounded knapsack (minimization) 
เพราะเหรียญถูกใช้ได้ไม่จำกัดจำนวน

เมื่อเติม `x` ตั้งแต่ 1 ถึง `M` จะได้คำตอบ `dp[M]`  
หาก `dp[M]` ยังคงมีค่าใหญ่กว่าค่าที่เป็นไปได้ (เช่นกำหนดเป็น `M+1`)
แสดงว่าไม่สามารถแปลงเงินได้ (ไม่มีข้อมูลในโจทย์)

## 3. อธิบายโค้ด + ยกตัวอย่าง testcase

โค้ดใน `coin_change.cpp` อ่านจำนวนเหรียญ `N` และมูลค่าเป้าหมาย `M`  
ตามด้วยค่าธรรมเนียมแต่ละเหรียญ

โครงสร้างโค้ด:
```cpp
vector<int> coins(N);
for (int i = 0; i < N; i++) cin >> coins[i];
vector<int> dp(M+1, M+1);
dp[0] = 0;

for (int coin : coins) {
    for (int j = coin; j <= M; j++) {
        dp[j] = min(dp[j], dp[j-coin] + 1);
    }
}
cout << dp[M] << '\n';
```
- แถว `dp` เริ่มเป็น `M+1` (ค่ามหาศาลเท่ากับ "infinity")
- อัพเดตลูปภายนอกตามเหรียญ ลูปภายในตามมูลค่า
  (ทำให้โค้ดเป็นวิธี "Coin-first" ซึ่งยังถูกต้องสำหรับ unbounded)
- ผลลัพธ์เป็น `dp[M]` ซึ่งเท่ากับจำนวนเหรียญขั้นต่ำ

### ตัวอย่างอินพุต
```
4 28
10 5 2 1
```
เหรียญมีค่า `[10,5,2,1]` เราต้องเขียน 28
- วิธี optimal: `10 + 10 + 5 + 2 + 1` = 5 เหรียญ  
(`dp[28]` จึงเป็น 5)  
ผลลัพธ์: **5**

## 4. Time Complexity

- ลูปภายนอกรัน `N` ครั้ง (จำนวนเหรียญ)  
- ลูปภายในรัน `M` ครั้ง (มูลค่าจนถึงเป้าหมาย)  
- การอัพเดตภายในเป็น `O(1)`

**เวลา**: `O(N * M)`  
**พื้นที่**: `O(M)` สำหรับอาเรย์ `dp`  

(สามารถสลับลำดับลูปเป็น `for j` ภายนอก `for coin` ภายในได้เช่นกัน)

เทคนิคการแปลงราคาเป็นลำดับจำนวนต่ำสุด โดย recurrence
ง่ายและมีประสิทธิภาพในเชิงเวลาและพื้นที่
