# ↘️ Diagonal Sum (ผลรวมเส้นทแยงมุมสูงสุด)

## 1. วิเคราะห์โจทย์ Diagonal Sum
โจทย์กำหนดให้ตาราง 2 มิติ $A$ ขนาด $n \times n$ (มี $n$ แถว และ $n$ คอลัมน์) โดยอ้างอิงตำแหน่งเป็น `A[r][c]` 
เป้าหมายคือการหา **"ผลรวมเส้นทแยงมุมที่มากที่สุด"** (Maximum Diagonal Sum) โดยผลรวมตามแนวทแยง (Diagonal) นั้นจะลากไปในทิศทางขวาและลงล่างพร้อมกัน (ความชันเป็นลบ) กล่าวคือ การนำตัวเลขในช่อง `A[i][j], A[i+1][j+1], A[i+2][j+2], ... , A[i+k-1][j+k-1]` อย่างต่อเนื่องกันมาบวกกัน 

สิ่งที่เราต้องพิจารณาคือ **เส้นทแยงมุมมีได้หลายเส้น** (จากจุดเริ่มต้นขอบบนและขอบซ้ายทั้งหมด) และในแต่ละเส้นนั้น เราสามารถเลือกความยาวช่วงการเชื่อมต่อ (Subsegment) เพื่อหาผลรวมที่เยอะที่สุดได้ เหมือนกับการดึงค่าตามแนวทแยงมุมออกมาเป็น Array 1 มิติ แล้วหาค่า **Maximum Contiguous Subarray Sum** นั่นเอง

## 2. วิเคราะห์การใช้ Kadane's Algorithm และเขียนความสัมพันธ์เวียนเกิด (Recurrence Relation)
ปัญหาการหาผลรวมติดกันที่มากที่สุดใน Array 1 มิตินั้น สามารถใช้อัลกอริทึมที่มีชื่อเสียงอย่าง **Kadane’s Algorithm** ซึ่งเป็นหนึ่งในรูปแบบของ Dynamic Programming ที่มีประสิทธิภาพสูงสุด 

**แนวคิดของ Kadane's Algorithm:**
ขณะที่เราบวกผลรวมสะสมไปเรื่อยๆ ตามเส้นทแยงมุม หากพบว่าผลบวกสะสมรวมมีค่าติดลบ (`< 0`) แปลว่าลำดับที่เราสะสมมานั้นเป็นภาระ ทำให้ค่าโดยรวมลดลง ดังนั้นเราจึงควร "ทิ้ง" ผลสะสมเดิม แล้วเริ่มต้นนับ Subsegment ใหม่ที่ตัวเลขปัจจุบันแทน แต่ถ้าผลสะสมยังเป็นบวกอยู่ ก็สามารถนำไปบวกเพิ่มกับตัวถัดไปได้

**สมการ Recurrence Relation:**
กำหนดให้ $dp[m]$ คือผลรวมย่อยที่มากที่สุดที่มาจบตรงพจน์ที่ $m$ ในลำดับเส้นทแยงมุมนั้นๆ และ $V[m]$ คือค่าตัวเลขในช่องตารางปัจจุบัน
`dp[m] = max(V[m], dp[m-1] + V[m])`

*ในส่วนของโค้ด เราอาจไม่ได้จอง Array `dp` ไว้เพื่อประหยัดพื้นที่ แต่ใช้ตัวแปรชื่อ `current_max` ในการจดจำ `dp[m-1]` แทน*

## 3. อธิบายโค้ดและยกตัวอย่าง Test Case
**อธิบายโค้ดหลัก:**
1. โปรแกรมรับค่า $n$ และตารางตัวเลขใส่ใน `vector<vector<int>> A`
2. สร้าง Lambda function ชื่อ `process_diagonal(start_row, start_col)` เพื่อรับหน้าที่ประมวลผลเส้นทแยงมุมแต่ละเส้น โดยใช้แนวคิด Kadane's Algorithm 
   * ให้ตัวแปร `row` และ `col` เริ่มจากจุดตั้งต้นและขยับทีละ `+1` พร้อมๆ กัน (วิ่งทะแยงเฉียงลงขวา)
   * หากผลสะสมเก่า `current_max` ติดลบ (น้อยกว่า 0) จะโดนรีเซ็ตให้เท่ากับค่าในเซ أنّลปัจจุบัน (`value`)
   * แต่ถ้าเป็นบวก จะเอาของเก่าบวกของใหม่ `current_max + value`
   * และทุกๆ ขั้นตอนจะมีการอัปเดต `global_max` เพื่อจดจำสถิติผลรวมที่มากที่สุดตลอดกาล
3. โปรแกรมกระตุ้น (Trigger) จุดเริ่มต้นของเส้นทแยงมุม 2 ด้าน:
   * **เส้นทแยงมุมที่เริ่มจากขอบบน (แถวแรกสุด):** วนรับจุด `(0, c)` สำหรับ `c` ตั้งแต่ $0$ ถึง $n-1$
   * **เส้นทแยงมุมที่เริ่มจากขอบซ้ายสุด (คอลัมน์แรกสุด ไม่รวมจุด 0,0 ที่ทำไปแล้ว):** วนรับจุด `(r, 0)` สำหรับ `r` ตั้งแต่ $1$ ถึง $n-1$
4. เมื่อไล่ครบทุกความเป็นไปได้ ก็ปริ้นค่าสถิติที่ดีที่สุด `global_max` ออกมา

**ยกตัวอย่าง Test Case:**
**Input:**
```text
4
1 2 3 4
-2 -5 2 -5
6 3 -7 1
3 -2 7 -9
```

**ตัวอย่างการทำงานบางส่วน (Trace):**
* จุดเริ่มต้น `(0,0)`: ลำดับคือ `[1, -5, -7, -9]` -> Kadane ได้ค่าสูงสุดคือ `1`
* จุดเริ่มต้น `(0,1)`: ลำดับคือ `[2, 2, 1]` -> Kadane ได้ค่าสูงสุดคือ `2 + 2 + 1 = 5`
* จุดเริ่มต้น `(1,0)`: ลำดับคือ `[-2, 3, 7]` -> Kadane หาค่าสูงสุดได้ดังนี้:
  1. ค่าตัวแรก `value = -2` -> `current_max = -2`
  2. ค่าตัวสอง `value = 3` -> เพราะของเก่า `-2 < 0` เลยรีเซ็ตเอาใหม่เป็น `3` -> `current_max = 3`
  3. ค่าตัวสาม `value = 7` -> ของเก่า `3 > 0` เอามาบวกสะสมได้ `3 + 7 = 10`
* จุดเริ่มต้น `(2,0)`: ลำดับคือ `[6, -2]` -> Kadane ได้ค่าสูงสุดคือ `6`

เมื่อตรวจสอบเส้นทแยงมุมครบทั้งหมด จะพบว่าค่าจากเส้นที่เริ่มแถว `(1,0)` ตรงเลข 3 และ 7 ได้ผลลัพธ์เป็นชิ้นส่วนย่อย (Subsegment) ที่มีผลรวมเยอะที่สุด คือ `10` ซึ่งตรงกันกับเอาต์พุต

## 4. Time Complexity
**ความซับซ้อนด้านเวลา (Time Complexity):** **$O(n^2)$**
เหตุผล: การหาผลรวมด้วย Kadane's algorithm ใน 1 เส้นทแยงมุม ใช้เวลาทำงานเป็นเส้นตรงตามความยาวเส้นนั้น และอัลกอริทึมถูกออกแบบให้วนลูปตรวจสอบทุกๆ สมาชิก (Element) ภายในตาราง 2 มิติอย่างละ 1 คร้ังพอดีไม่มีการย้อนกลับ โดยตารางมีขนาด $n \times n$ เมื่อตรวจสอบครบทั้งตารางจึงมีจำนวนรอบการทำงานโดยรวมอยู่ที่ประมาณ $n^2$ ครั้ง ทำให้ Time Complexity ตกอยู่ที่ **$O(n^2)$** ซึ่งเป็นระยะเวลาที่เหมาะสมและเร็วที่สุด (Optimal) ในแง่ของการต้องดึงค่ามาประมวลผลทุกตัวในตาราง

*(เพิ่มเติม)*
**ความซับซ้อนด้านพื้นที่ (Space Complexity):** **$O(n^2)$**
เหตุผล: โปรแกรมมีการใช้พื้นที่เก็บตัวแปรโครงสร้าง 2 มิติ `vector<vector<int>> A(n, vector<int>(n))` เพื่อบันทึกค่าของข้อมูลทั้งหมด ซึ่งแปรผันตามจำนวนอินพุต $n^2$ ตัวพอดี ส่วนการค้นหาเราไม่ได้สร้าง 1D Array มาคั่นกลาง แต่ใช้ตัวแปร `current_max` ประมวลผลทีละตัว จึงไม่ได้เพิ่มพื้นที่มากไปกว่านี้
