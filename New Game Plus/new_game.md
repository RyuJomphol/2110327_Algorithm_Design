# New Game Plus

## 1. วิเคราะห์โจทย์ New Game Plus

เขาวงกตเป็นตารางขนาด `R` แถว × `C` คอลัมน์ แต่ละช่องเป็นห้องที่อาจถูกบล็อก (ค่า 1)
ผู้เล่นเริ่มจากห้องในคอลัมน์ 1 (แถวใดก็ได้ที่ไม่บล็อก) และต้องไปถึงคอลัมน์ `C` (แถวใดก็ได้)

แต่ละห้องมีประตูสามแบบที่พาไปยังคอลัมน์ถัดไป:
- ประตู `X`: ไปยัง `(r-1, c+1)` (บนขวา)
- ประตู `Y`: ไปยัง `(r,   c+1)` (กลางขวา)
- ประตู `Z`: ไปยัง `(r+1, c+1)` (ล่างขวา)

กฎการเดินที่สำคัญ:
- ห้ามเลือกประตูเดียวกันกับที่เพิ่งเลือกมาในขั้นก่อนหน้า (ห้ามซ้ำแบบติดกัน)
- ห้ามเข้าห้องที่บล็อก (`1`) และห้ามออกนอกขอบตาราง
- เส้นทางที่ต่างกันถ้ามีลำดับห้องที่ผ่านต่างกัน (ลำดับสำคัญ)

ต้องนับจำนวนเส้นทางที่เป็นไปได้ทั้งหมดจากคอลัมน์ 1 → คอลัมน์ C โดยคืนผลลัพธ์ mod `100000007`.

## 2. วิเคราะห์ที่มาสมการ Recurrence Relation

นิยามสถานะ DP ดังนี้:
- `dp[r][c][t]` = จำนวนเส้นทางที่มาถึงห้อง `(r,c)` โดยประตูล่าสุดที่ใช้เป็นชนิด `t`
  โดย `t = 0` หมายถึงประตู `X`, `t = 1` หมายถึง `Y`, `t = 2` หมายถึง `Z`.

ความหมาย: สถานะนี้เก็บลำดับของประตูที่ใช้จนถึงตำแหน่งปัจจุบัน ทำให้เราสามารถบังคับเงื่อนไข
"ห้ามใช้ประตูเดียวกับครั้งก่อนหน้า" ได้ง่าย

ฐานเริ่มต้น (ตั้งค่าเริ่มต้นที่คอลัมน์ 2 จากการออกจากคอลัมน์ 1):
- จากห้อง `(r,1)` ที่ไม่บล็อก สามารถเลือกประตูไปยัง `(r-1,2)`, `(r,2)`, `(r+1,2)` ตามความเป็นไปได้
  และเพิ่ม `dp[target_row][2][t] += 1` ตามประเภทประตูที่ใช้

การอัพเดตทั่วไปเมื่ออยู่ที่ `(r,c)` และต้องไปยังคอลัมน์ `c+1`:
- หากต้องการใช้ประตู `X` (ไป `(r-1,c+1)`) ต้องตรวจสอบว่าประตูก่อนหน้าไม่ใช่ `X` ⇒ รวมมาจากสถานะที่มี last = `Y` หรือ `Z`:
  ```
  dp[r-1][c+1][0] += dp[r][c][1] + dp[r][c][2]
  ```
- สำหรับ `Y` (ไป `(r,c+1)`): มาจาก last = `X` หรือ `Z`:
  ```
  dp[r][c+1][1] += dp[r][c][0] + dp[r][c][2]
  ```
- สำหรับ `Z` (ไป `(r+1,c+1)`): มาจาก last = `X` หรือ `Y`:
  ```
  dp[r+1][c+1][2] += dp[r][c][0] + dp[r][c][1]
  ```

ทุกการอัพเดตต้องตรวจสอบเงื่อนไขต่อไปนี้ก่อนเพิ่มค่า:
- เซลล์เป้าหมายต้องอยู่ในกริด (1 ≤ row ≤ R) และไม่บล็อก (grid[row][c+1] == 0)
- ใช้ modulo `MOD = 100000007` ทุกครั้งเพื่อลดขนาดตัวเลข

คำตอบสุดท้าย: ผลรวมของ `dp[r][C][0] + dp[r][C][1] + dp[r][C][2]` สำหรับทุกแถว `r` ที่ `grid[r][C] == 0`.
(กรณีพิเศษ: ถ้า `C == 1` ให้จำนวนเส้นทางเท่ากับจำนวนห้องในคอลัมน์ 1 ที่ไม่บล็อก)

## 3. อธิบายโค้ด (`new_game_plus.cpp`) + ตัวอย่าง testcase

สรุปโครงร่างโปรแกรมที่แนบมา:
- อ่าน `R`, `C` และตาราง `grid[1..R][1..C]` (0 = ว่าง, 1 = บล็อก)
- ประกาศ `dp[R+1][C+1][3]` เริ่มจากศูนย์ และกำหนด `MOD = 100000007`
- สำหรับทุกแถว `r` ที่ `grid[r][1] == 0` สร้างการก้าวแรกไปยังคอลัมน์ `2` (ถ้าอยู่ในกริด):
  - ไป `(r-1,2)` ด้วย last = `X` → `dp[r-1][2][0] += 1` (ถ้าใช้ได้)
  - ไป `(r,2)` ด้วย last = `Y` → `dp[r][2][1] += 1`
  - ไป `(r+1,2)` ด้วย last = `Z` → `dp[r+1][2][2] += 1`
- ทำลูป `c = 2 .. C-1` และสำหรับแต่ละห้อง `(r,c)` ที่ไม่บล็อก ทำการอัพเดตสถานะไปยัง `c+1`
  ตามสูตร recurrence ที่ยกมา โดยห้ามเลือกประตูเดียวกับ last ที่เก็บในสถานะปัจจุบัน
- สรุปผลรวมที่คอลัมน์ `C` แล้วพิมพ์ผลลัพธ์ modulo `MOD`

ข้อสังเกตสำคัญเกี่ยวกับโค้ด:
- ตัวแปร `dp[r][c][t]` เก็บจำนวนเส้นทางที่ลงท้ายด้วยประตู `t` ณ ตำแหน่งนั้น ๆ
- การห้ามเลือกประตูซ้ำติดกันถูกบังคับโดยการไม่รวมสถานะที่มี last เท่ากับประตูที่ต้องการเลือก
- โค้ดจัดการขอบเขตกริดและห้องบล็อกไว้ก่อนการอัพเดต

### Testcase (จากโจทย์)
อินพุต:
```
3 3
0 1 0
0 0 1
0 1 0
```
ตาราง (0 = ว่าง, 1 = บล็อก):
```
(1,1)=0  (1,2)=1  (1,3)=0
(2,1)=0  (2,2)=0  (2,3)=1
(3,1)=0  (3,2)=1  (3,3)=0
```
อธิบายสั้น ๆ: ผู้เล่นเริ่มจากคอลัมน์ 1 (แถว 1..3 ที่ว่าง) แล้วเดินไปคอลัมน์ 3 โดยไม่เข้าห้องบล็อกและห้ามใช้ประตูซ้ำติดกัน

ผลลัพธ์จากโค้ด: **4**  
(โค้ดจะคำนวณจำนวนเส้นทางทั้งหมดและคืนค่าตามตัวอย่าง)

## 4. Time Complexity

- โปรแกรมสแกนเริ่มต้นทุกแถวในคอลัมน์ 1 → O(R)
- ลูปหลักวิ่งตามคอลัมน์ `c = 2..C-1` และแถว `r = 1..R` ทำงาน O(1) ต่อเซลล์ (รวมการอัพเดต 3 ครั้ง)

ดังนั้นเวลาโดยรวมคือ **O(R * C)**

พื้นที่ที่ใช้คืออาเรย์ `dp[R+1][C+1][3]` → **O(R * C)** (สามารถลดเป็น O(R * 3) หรือ O(R) หากทำเป็น rolling per column)

### สรุป
วิธีการนี้ใช้ DP ที่เก็บสถานะ `last door` เพื่อบังคับเงื่อนไขห้ามใช้ประตูซ้ำติดกันอย่างเรียบง่ายและมีประสิทธิภาพ
การนับเส้นทางทั้งหมดทำได้โดยการกระจายจำนวนเส้นทางจากคอลัมน์หนึ่งไปยังคอลัมน์ถัดไปโดยตรวจสอบกริดและขอบเขตเสมอ
