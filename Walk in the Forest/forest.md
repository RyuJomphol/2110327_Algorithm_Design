# 🌲 Walk in the Forest (เดินลุยป่า)

## 1. วิเคราะห์โจทย์ Walk in the forest
โจทย์กำหนดตารางคะแนนขนาด $N$ แถว และ $M$ คอลัมน์ เป้าหมายของเราคือการเดินทางจากมุมซ้ายบนคือช่อง `(1, 1)` ไปยังมุมขวาล่างคือช่อง `(N, M)` โดยผ่านกฎกติกาการเดิน 3 รูปแบบและสะสมคะแนนระหว่างทางให้ได้ **"มากที่สุด"**

**กติกาการเดิน:** จากช่องพิกัด `(r, c)` ปัจจุบัน สามารถเลือกก้าวเดินไปได้ 3 ทิศทางคือ
1. เดินลงล่าง ไปยังช่อง `(r+1, c)` -> ได้คะแนน 1 เท่าของช่องเป้าหมาย
2. เดินไปทางขวา ไปยังช่อง `(r, c+1)` -> ได้คะแนน 1 เท่าของช่องเป้าหมาย
3. เดินทะแยงมุมขวาล่าง ไปยังช่อง `(r+1, c+1)` -> **ได้คะแนนเป็น 2 เท่า** 🌟 ของช่องเป้าหมาย

ปัญหานี้เป็นโครงสร้างพื้นฐานของเรื่อง Pathfinding with Maximum Rewards ซึ่งสามารถจัดการด้วย **Dynamic Programming (Bottom-Up 2D Tabulation)** เพื่อหลีกเลี่ยงการคำนวณเส้นทางเดิมซ้ำ โดยแนวทางที่เราจะใช้คือมองย้อนกลับว่า ถ้าเราอยากรู้ว่าช่องเป้าหมายมีคะแนนดีสุดเท่าไร เราก็ต้องรู้คะแนนสะสมสูงสุดของจุดทางผ่านก่อนหน้าเสียก่อน 

## 2. วิเคราะห์ที่มาสมการ Recurrence Relation
ในเทคนิค DP ของการหาเส้นทางเดินบนตาราง เราจะสร้างตาราง `dp[r][c]` ขึ้นมาเพื่อเก็บ "คะแนนสะสมที่สูงที่สุดเมื่อเดินมาหมาหมุดที่พิกัด `(r, c)`"
การจะมาถึงหมุด `(r, c)` ได้ แปลว่าก้าวก่อนหน้าที่เราจะมาถึงที่นี่ เราต้องมาจากช่องข้างบน `(r-1, c)`, ช่องข้างซ้าย `(r, c-1)` หรือช่องทะแยงซ้ายบน `(r-1, c-1)` ช่องใดช่องหนึ่งเท่านั้น 

ดังนั้น เราต้องเปรียบเทียบว่าการมาจากทิศไหน จะให้ผลรวมที่คุ้มค่ากว่ากัน:
1. `from_above` = เอาคะแนนสะสมจากช่องข้างบน `dp[r-1][c]` + รวมคะแนนปกติของช่องปัจจุบัน `grid[r][c]`
2. `from_left` = เอาคะแนนสะสมจากช่องข้างซ้าย `dp[r][c-1]` + รวมคะแนนปกติของช่องปัจจุบัน `grid[r][c]`
3. `from_diagonal` = เอาคะแนนสะสมจากช่องทะแยงมุมซ้ายบน `dp[r-1][c-1]` + **รวมคะแนนสองเท่า** ของช่องปัจจุบัน `(2 * grid[r][c])`

**สมการ Recurrence Relation:**
`dp[r][c] = max(from_above, from_left, from_diagonal)`
*(โดยที่เราจะพิจารณาทิศทางเหล่านั้นได้ ก็ต่อเมื่อมันไม่ล้นทะลุขอบแผนที่ออกไป)*

**Base Cases (กรณีตั้งต้น):**
ณ จุด Start `(1, 1)` เราไม่ต้องการการก้าวมาจากไหนคะแนนตั้งต้นของจุดนี้ก็คือคะแนนของตัวมันเองเพียวๆ
`dp[1][1] = grid[1][1]`

## 3. อธิบายโค้ดและยกตัวอย่าง Testcase
**การทำงานของโค้ด:**
1. โปรแกรมรับค่าตัวแปรมิติ $n, m$ แล้วสร้างอาเรย์ 2 มิติ คือ `grid` สำหรับเก็บข้อมูลแผนที่ดิบ และ `dp` พร้อมเซ็ตตารางเป็นรอบข้าง 0 ทิ้งไว้ (`vector<vector<int>> dp(n + 1, vector<int>(m + 1, 0))`) โดยตารางนี้มีขนาดเผื่อบวก 1 ด้วยเพื่อหลีกเลี่ยงการชี้ Index 0
2. ลูปใส่ตัวเลขให้ตารางคะแนน เริ่มตั้งแต่ `1` ถึง `n` และ `1` ถึง `m`
3. กำหนด Base case: `dp[1][1] = grid[1][1]`
4. เริ่มลูปค้นหาและอัปเดตตารางคะแนน โดยวนลูปตั้งแต่ซ้ายไปขวา และบนลงล่าง `(r=1..n)` และ `(c=1..m)`
   * โปรแกรมจะข้ามจุด `(1,1)` ไปทันทีเพราะมี Base case แล้ว
   * เซ็ตตัวรับการคำนวณล่วงหน้าเป็น -1 (`from_above = -1`, `from_left = -1`, `from_diagonal = -1`)
   * คอยเช็คขอบให้ปลอดภัย `if (r > 1)` ถึงจะอ่านค่า `from_above` ได้, โซนเส้นสายก็เช่นกัน
   * หากจุดปลอดภัย นำคำนวณแต่ละเส้นทาง โดยเฉพาะเส้นทาง `from_diagonal` ที่ได้คูณสอง
   * ฟังก์ชันลงเอยด้วยการนำ `max({from_above, from_left, from_diagonal})` ทิ้งรับเป็นคะแนนสูงสุดประจำช่อง `dp[r][c]`
5. เมื่อลูปทำงานสำเร็จทั้งตาราง จุดหมายสุดท้ายคือช่องมุมขวาล่าง ก็คือ `dp[n][m]` จะตีพิมพ์เป็น Output

**ยกตัวอย่าง Test Case:**
**Input:** ขนาด $3 \times 3$
```text
 1  1  10
 1  7  10
 1 10  20
```

**Trace จำลองผลรวม (DP Matrix):**
* **เริ่มที่ `dp[1][1]`**: คะแนน = 1 
* **แถวที่ 1 (เดินได้แค่ขวาต่อกันไปรวดเดียว):**
  * `[1][2]` (จากซ้าย) = 1 + 1 = 2
  * `[1][3]` (จากซ้าย) = 2 + 10 = 12
* **แถวที่ 2:**
  * `[2][1]` (จากบน) = 1 + 1 = 2
  * `[2][2]` (พิกัดเลข 7):
    * จากบน: `dp[1][2] + 7 = 2 + 7 = 9`
    * จากซ้าย: `dp[2][1] + 7 = 2 + 7 = 9`
    * จากทะแยงมุม `(1,1)` : `dp[1][1] + (7*2) = 1 + 14 = 15` 🌟 คุ้มสุด! เลือกลงจุดนี้ $\rightarrow dp[2][2] = 15$
  * `[2][3]` (พิกัดเลข 10): 
    * จากบน: `12 + 10 = 22`
    * จากซ้าย: `15 + 10 = 25`
    * จากทะแยง `(1,2)`: `2 + (10*2) = 22`
    $\rightarrow \max$ คือ 25 $\rightarrow dp[2][3] = 25$
* **แถวที่ 3:**
  * `[3][1]`: `dp[2][1] + 1 = 2 + 1 = 3`
  * `[3][2]` (พิกัดเลข 10): 
    * ทะแยงดีสุด: `dp[2][1] + 20` = `2 + 20 = 22` 
    $\rightarrow dp[3][2] = 22$ (เทียบกับมาจากบน `2+10=12`, มาซ้าย `3+10=13`)
  * `[3][3]` (พิกัดเลข 20 จุดหมายชัยชนะ):
    * จากบน: `dp[2][3] + 20` = `25 + 20 = 45`
    * จากซ้าย: `dp[3][2] + 20` = `22 + 20 = 42`
    * จากทะแยง `(2,2)`: `dp[2][2] + (20*2)` = `15 + 40 = 55` 🌟
    $\rightarrow \max$ คือ **55**! $\rightarrow dp[3][3] = 55$

ผลลัพธ์ของ `dp[3][3]` คือ `55` ซึ่งเป๊ะกับค่า Output ที่โจทย์แสดงให้ดูพอดีครับ

## 4. Time Complexity
**ความซับซ้อนด้านเวลา (Time Complexity):** **$O(N \times M)$**
เหตุผล: การแก้โจทย์ในวิธีดังกล่าว เราไม่ได้ใช้การค้นหาแบบ Graph Search ที่จะเจอทางแยกเต็มไปหมด แต่เราลดโครงสร้างลงให้เป็นเพียงแค่การวนลูปซ้อน `for (int r = 1; r <= n; r++)` คลุมด้วยคอลัมน์ `for (int c = 1; c <= m; c++)` ส่งผลให้ทุกๆ ข้อมูลในตารางถูกพิจารณาและประมวลผลแค่ทีละครั้งอย่างเป็นระบบ (รวมเป็นจำนวน $N \times M$ รอบโดยประมาณ) โดยในแต่ละรอบมีการเปรียบเทียบแค่ 3 ทางเลือก $O(1)$ เวลาจึงจัดอยู่ในระดับเส้นตรงเทียบกับขนาดตารางครับ

*(เพิ่มเติม)*
**ความซับซ้อนด้านพื้นที่ (Space Complexity):** **$O(N \times M)$**
เหตุผล: โค้ดมีการประกาศตัวแปร 2D Vector เต็มขนาดเพื่อเก็บประวัติตารางตั้งต้น `grid` และพื้นที่ประเมิน `dp` ขนาด $N \times M$ ทั้งสิ้น จึงใช้ความจำ Memory ในระดับค่อนข้างเต็มพิกัด (แต่สามารถลดไซส์ตารางลงเป็น $O(M)$ ได้ หากเลิกจำประวัติเกินกว่าแถวล่าสุดเพียง 2-3 แถว)
