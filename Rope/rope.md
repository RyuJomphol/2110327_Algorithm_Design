# 🪢 Rope (การตัดเชือก)

## 1. วิเคราะห์โจทย์ Rope
โจทย์กำหนดว่ามะนาวมีเชือกที่มีความยาว $n$ เมตร และต้องการตัดเชือกเส้นนี้ออกเป็นชิ้นเล็กๆ โดยมีเงื่อนไขดังนี้:
1. เชือกแต่ละชิ้นที่ถูกตัดออกมาต้องมีความยาวตรงกับ $a$, $b$, หรือ $c$ เมตรเท่านั้น
2. ห้ามมีเศษเชือกเหลือทิ้ง หมายความว่าผลรวมของความยาวทุกชิ้นที่ตัดออกมาต้องเท่ากับ $n$ พอดี
3. เป้าหมายคือต้องการหา **จำนวนชิ้นของเชือกที่มากที่สุดเท่าที่จะตัดได้** 

ปัญหาแนวนี้เป็นปัญหาการหาค่าสูงสุดแบบนับจำนวนชิ้น (Maximization of counts) ซึ่งสามารถแก้ได้โดยใช้เทคนิค **Dynamic Programming (DP)** เพราะการตัดเชือกความยาว $n$ ให้ได้จำนวนชิ้นมากที่สุด สามารถแบ่งคิดจากปัญหาขนาดย่อยๆ เช่น การตัดเชือกความยาว $n-a$, $n-b$, หรือ $n-c$ ให้ได้จำนวนชิ้นมากที่สุด แล้วจึงนำมาบวกเพิ่มอีก 1 ชิ้น (ชิ้นสุดท้ายที่ยาว $a, b,$ หรือ $c$)

## 2. วิเคราะห์ที่มาสมการ Recurrence Relation
ให้ `dp[i]` แทน "จำนวนชิ้นเชือกที่มากที่สุดที่สามารถตัดได้จากเชือกความยาว $i$ เมตร"
โดยเริ่มต้น ถ้าเรามีเชือกความยาว $i$ เมตร เราสามารถเลือกตัดได้ 3 แบบตามความยาวที่กำหนด ($a$, $b$, หรือ $c$):
- ถ้าเราเลือกตัดออก $a$ เมตร เราจะเหลือเชือกความยาว $i-a$ เมตร (โดยจะได้ชิ้นนี้มา 1 ชิ้น)
- ถ้าเราเลือกตัดออก $b$ เมตร เราจะเหลือเชือกความยาว $i-b$ เมตร (บวกอีก 1 ชิ้น)
- ถ้าเราเลือกตัดออก $c$ เมตร เราจะเหลือเชือกความยาว $i-c$ เมตร (บวกอีก 1 ชิ้น)

เพื่อให้ได้จำนวนชิ้นมากที่สุด เราจะต้องพิจารณาทางเลือกทั้ง 3 ทาง และเลือกทางที่ให้ค่าย่อยในอดีตมากที่สุด

**สมการ Recurrence Relation:**
`dp[i] = max( dp[i-a], dp[i-b], dp[i-c] ) + 1` 
*(โดยมีเงื่อนไขว่าความยาว $i$ ต้องมากกว่าหรือเท่ากับค่าที่หักออกไป และค่า $dp$ ย้อนหลังจะต้องเป็นสถานะที่ไปถึงได้/สามารถตัดลงตัวได้)*

**Base Cases (กรณีฐานเริ่มต้น):**
- เริ่มต้นให้ `dp` ของทุกๆ ความยาวเป็น `-1` เพื่อระบุว่าเป็นความยาวที่ "ยังไม่สามารถตัดให้ลงตัวได้"
- กำหนด `dp[0] = 0` เพราะเชือกความยาว 0 เมตร ย่อมหมายถึงยังไม่ได้ถูกตัด (ได้ 0 ชิ้น) และไม่มีเศษเหลือ ถือเป็นจุดเริ่มต้นการนับที่ถูกต้อง

## 3. อธิบายโค้ดและยกตัวอย่าง Testcase
**การทำงานของโค้ด:**
1. โปรแกรมรับค่าตัวแปร $n, a, b, c$ 
2. สร้างอาเรย์ `vector<int> dp(n + 1, -1)` โดยตั้งค่าเริ่มต้นทุกช่องเป็น `-1` ป้องกันการเผลอเอาความยาวที่ตัดไม่ลงตัวอยู่แล้วมาคิดคำนวณ 
3. กำหนด Base case: `dp[0] = 0` 
4. เริ่มลูปค้นหาค่าตั้งแต่ความยาว `i = 1` ถึง `n`:
   - โปรแกรมจะเช็คชอยส์ในการตัดด้วยความยาว $a, b,$ และ $c$ ตามลำดับ
   - เงื่อนไข `if (i >= a && dp[i - a] != -1)` หมายความว่า เชือกปัจจุบันความยาว $i$ จะต้องยาวพอที่จะให้ตัดชิ้นขนาด $a$ ได้ และถ้าตัดไปแล้ว ความยาวที่เหลือ $i - a$ เมตร จะต้องเป็นความยาวที่ "สามารถถูกตัดจนไม่มีเศษเหลือได้" (เช็คว่า `dp` ไม่ใช่ `-1`)
   - หากเข้าเงื่อนไข จะอัปเดตค่า `dp[i]` ให้เป็นค่ามากสุดระหว่างตัวมันเองในรอบอื่นเทียบกับ `dp[i-a] + 1` 
   - โปรแกรมย้ำสเต็ปเดิมกับ $b$ และ $c$ สะสมค่า `max` ออกมาที่ดีที่สุด
5. พอสิ้นสุดลูป พิมพ์คำตอบ `dp[n]` ซึ่งก็คือจำนวนชิ้นตัดได้มากสุดของเชือกที่ความยาว $n$ 

**ยกตัวอย่าง Test Case:**
**Input:** `10 2 3 4` ($n=10, a=2, b=3, c=4$)
**การดำเนินการใน DP (พิจารณาเฉพาะตัวหลัก):**
- `dp[0] = 0`
- `dp[1] = -1` (ไม่เข้าเงื่อนไขเพราะน้อยกว่า 2, 3, 4 ทั้งหมด)
- `dp[2]`: มาจากการตัด 2 จะได้ `dp[2-2] + 1` -> `dp[0] + 1` = `1`
- `dp[3]`: มาจากการตัด 3 จะได้ `dp[3-3] + 1` -> `dp[0] + 1` = `1`
- `dp[4]`: ตัด 2 จะได้ `dp[4-2] + 1` = `dp[2] + 1` = `2` / ตัด 4 จะได้ `dp[0] + 1` = `1` -> ค่า max คือ `2` 
- `dp[5]`: ตัด 2 เหลือ 3 (`dp[3]+1` = 1+1=2) / ตัด 3 เหลือ 2 (`dp[2]+1` = 1+1=2) -> ค่า max คือ `2`
- `dp[6]`: ตัด 2 เหลือ 4 (`dp[4]+1` = 2+1=3) / ตัด 3 เหลือ 3 (`dp[3]+1` = 1+1=2) / ตัด 4 เหลือ 2 (`dp[2]+1` = 1+1=2) -> ค่า max คือ `3`
- ...
- `dp[10]`: มาจากการเทียบระหว่าง 
  1. ตัดเพิ่มทีละ 2 เมตร (`dp[8] + 1` = `4 + 1` = `5`)
  2. ตัดเพิ่มทีละ 3 เมตร (`dp[7] + 1` = `3 + 1` = `4`)
  3. ตัดเพิ่มทีละ 4 เมตร (`dp[6] + 1` = `3 + 1` = `4`)
เลือกจำนวนชิ้นสูงที่สุด ดังนั้น `dp[10] = 5` ชิ้น **(ได้ Output: 5)** ซึ่งเกิดขึ้นจากการตัดชิ้นความยาว 2 เมตรจำนวน 5 ชิ้น (2+2+2+2+2 = 10 เมตร พอดี ไม่เหลือเศษ)

## 4. Time Complexity
**ความซับซ้อนด้านเวลา (Time Complexity):** **$O(n)$**
เหตุผล: โปรแกรมใช้ลูปวนรอบตัวแปร $i$ เพียงแค่ชั้นเดียว จากความยาว $1$ จนถึง $n$ ซึ่งเทียบเท่ากับ $n$ รอบ ในแต่ละรอบมีการตรวจสอบคำสั่ง `if` เล็กๆ น้อยๆ อย่างมาก 3 ครั้ง (เช็คเงื่อนไข $a, b, c$) และคำนวณ `max` ซึ่งถือว่าเป็น Operation ที่ใช้ระยะเวลาคงที่ (Constant Time หรือ $O(1)$) เมื่อนำมาคูณกับจำนวนรอบแล้ว จึงส่งผลให้ประสิทธิภาพเวลาเติบโตแปรผันตามขนาดของความยาว $n$ แบบเชิงเส้น 

*(เพิ่มเติม)*
**ความซับซ้อนด้านพื้นที่ (Space Complexity):** **$O(n)$**
เหตุผล: โค้ดประกาศใช้งาน `vector<int> dp(n + 1)` ซึ่งใช้เนื้อที่หน่วยความจำเพิ่มตามความยาว $n$ ตรงๆ เพื่อบันทึกประวัติการตัดจำนวนชิ้นที่ความยาวต่างๆ ในอดีต
