# 🧮 Matrix Chain Multiplication (การคูณเมทริกซ์แบบต่อเนื่อง)

## 1. วิเคราะห์โจทย์ Matrix Chain Multiplication
โจทย์กำหนดลำดับของมิติเมทริกซ์ (Matrix dimension sequence) จำนวน $N$ ตัว เพื่อนำไปใช้ระบุมิติของตัวเมทริกซ์ทั้งหมด ($M_1, M_2, ..., M_N$)
โดยที่เมทริกซ์ $M_i$ จะมีขนาดเท่ากับ $S_{i-1} \times S_i$ 

เรารู้ว่าการคูณเมทริกซ์ ขนาด $p \times q$ เข้ากับ $q \times r$ จะต้องใช้รอบการประมวลผล (Scalar multiplications) เท่ากับ $p \times q \times r$ ครั้ง 
และที่สำคัญ การคูณเมทริกซ์ต่างๆ หลายตัวต่อกันนั้น **มีคุณสมบัติการจัดหมู่ (Associative property)** คือไม่ว่าจะใส่วงเล็บคูณคู่ไหนก่อน ผลลัพธ์รวมของเมทริกซ์ก็จะเท่าเดิม
แต่ทว่าการ "เลือกใส่วงเล็บคูณคู่ไหนก่อนหลัง" ดันส่งผลทำให้จำนวนรอบ (Cost) ที่คอมพิวเตอร์ต้องคูณเลขแตกต่างกันได้อย่างมหาศาล 
ปัญหาของเราในข้อนี้คือการหาว่า **"เราควรจัดกลุ่มลำดับการคูณอย่างไร จึงจะทำให้คอมพิวเตอร์ใช้จำนวนรอบการคูณ (Cost) น้อยที่สุด"**

นี่คือหนึ่งในโจทย์ระดับตำนานของ **Dynamic Programming** ประเภท Interval DP (หรือ Range DP) ที่ต้องหาช่วงที่ดีที่สุดทีละขยายขนาดขึ้นไป

## 2. วิเคราะห์ที่มาสมการ Recurrence Relation
ให้ `dp[i][j]` คือ **จำนวนรอบการคูณ (Cost) ที่น้อยที่สุด** ในการเอาเมทริกซ์ก้อนที่ $i$ จนถึงเมทริกซ์ก้อนที่ $j$ มาคูณประสานกัน
การที่เราจะคูณก้อนที่ $i$ ถึง $j$ เข้าด้วยกันได้ ในก้าวสุดท้ายมันย่อมเกิดจากการเอาเมทริกซ์ที่ถูกยุบเป็น "ก้อนซ้าย" คูณกับ "ก้อนขวา" 
เราสามารถลองสับจุดแบ่ง (จุด $k$) ได้ทุกๆ ตำแหน่งตั้งแต่ $i$ ไปจนถึงก่อน $j$ ($k = i, i+1, ..., j-1$) เพื่อหาจุดตัด $k$ ที่ให้ผลลัพธ์ต่ำที่สุด

* **ก้อนซ้าย** จะเกิดจากการคูณเมทริกซ์ตั้งแต่ตัวที่ $i$ ถึง $k$ ใช้ Cost ค่าเท่ากับ `dp[i][k]` และเมทริกซ์สุดท้ายที่ยุบได้จะมีขนาด $S_{i-1} \times S_k$
* **ก้อนขวา** จะเกิดจากการคูณเมทริกซ์ตั้งแต่ตัวที่ $k+1$ ถึง $j$ ใช้ Cost ค่าเท่ากับ `dp[k+1][j]` และเมทริกซ์สุดท้ายที่ยุบได้จะมีขนาด $S_k \times S_j$
* **ค่าใช้จ่ายจังหวะคูณรวบยอด (Merge cost)** คือการเอาก้อนซ้ายและก้อนขวาที่ยุบเสร็จแล้วมาคูณกัน จะใช้รอบการทำงานเท่ากับ $S_{i-1} \times S_k \times S_j$

**สมการ Recurrence Relation:**
$$ dp[i][j] = \min_{i \le k < j} \Big( dp[i][k] + dp[k+1][j] + (S_{i-1} \times S_k \times S_j) \Big) $$

**Base Cases (กรณีฐานเริ่มต้น):**
`dp[i][i] = 0` (หากช่วงเริ่มและจบเป็นก้อนเดียวกัน คือไม่เกิดการคูณใดๆ ค่าใช้จ่ายย่อมเป็น 0)

## 3. อธิบายโค้ดและยกตัวอย่าง Testcase
**การทำงานของโค้ด:**
1. โปรแกรมรับค่า $N$ (จำนวนเมทริกซ์) และรับขนาดใส่ลง Array `S` ขนาด $N+1$ ตัว
2. สร้างตาราง 2D Vector ชื่อ `dp` ขนาด $(N+1) \times (N+1)$ ใส่ค่าเริ่มต้นทุกช่องเป็น 0
3. รันโครงสร้างลูปซ้อน 3 ชั้นระดับเอกลักษณ์ของ Interval DP:
   * **ลูปนอกสุด (L):** คือการกางความกว้างของช่วงที่เราจะยุบ (Length) เริ่มจากกว้าง $L=2$ (คว้ารวบ 2 ตัว) ขยายไปสุดจนถึงความกว้าง $L=N$ (คว้ารวบทั้งหมดครบวงจร) การทำลูปทำจากช่วงเล็กไปใหญ่นี้ช่วยรับประกันว่าค่าย่อย (Subproblems) จะถูกคำนวณไว้เตรียมพร้อมเสมอ
   * **ลูปชั้นสอง (i):** คือการเลื่อนหน้าต่างพิกัดจุดเริ่มต้น (Start index `i`) จากซ้ายไปขวา โดยจะทำให้จุดสุดท้าย `j = i + L - 1`
   * **ลูปในสุด (k):** คือการวนหาจุดตัด $k$ ภายในช่วง $[i, j-1]$ ซึ่งในส่วนนี้จะใช้รันสมการ DP หายอดรวมแต่ละรอยตัด แล้วเช็คหาค่า Min เอามาเก็บไว้ใน `dp[i][j]` (ตั้งค่าต้นไว้เป็นเลขเยอะมหาศาลอย่าง `LLONG_MAX`)
4. เมื่อลูปขยายจนคลุมครบความยาว $N$ จุด `dp[1][N]` จะกลายเป็นตู้คอนเทนเนอร์เก็บค่าผลลัพธ์ที่เกิดจากการสอยเส้นทางที่ดีที่สุดมารวมไว้ทั้งหมด

**ยกตัวอย่าง Testcase:**
**Input:** 
จำนวน 7 เมทริกซ์ ขนาดคือ `92 32 7 3 29 74 57 93` 
($S_0 = 92$, $S_1 = 32$, $S_2 = 7$, ... ไปจนถึง $S_7 = 93$)
**วิเคราะห์เส้นทางการจับคู่แบบย่อ:**
สมมติมีการจับกลุ่ม $M_0$ ถึง $M_6$ (ตามโจทย์ใช้ $N$ แบบ 0-index แต่ในโค้ดและทฤษฎีทั่วไปมักใช้ 1-index ก็เปรียบเป็น $M_1$ ถึง $M_7$)
โปรแกรมจะทำการหาจุดแบ่ง $k$ ดีที่สุดค่อยๆ ยุบขึ้นไปเรื่อยๆ จนระบบพบว่าการจับคู่วงเล็บเป็น **$M_1(M_2 M_3)(((M_4 M_5) M_6) M_7)$** จะช่วยให้หน้าต่างขนาดใหญ่อย่าง 92 กับ 93 ถูกกดดันเอาไว้คูณในสเต็ปท้ายๆ ซึ่งทำให้ผลรวมจำนวนการคูณสะสมนั้นใช้เพียงแค่ **70,167** ครั้งเท่านั้น ซึ่งระบบ DP การันตีให้แล้วว่าเป็นเส้นทางค่าใช้จ่ายรอบประมวลผลที่ต่ำที่สุด!
**Output: 70167**

## 4. Time Complexity
**ความซับซ้อนด้านเวลา (Time Complexity):** **$O(N^3)$**
เหตุผล: การแก้โจทย์ข้อนี้ใช้กลไกลูปซ้อนทำซ้ำทั้งหมด 3 ลูป ได้แก่: ลูปรัศมีความกว้าง $L$ ($O(N)$), ลูปหาจุดเริ่มต้น $i$ ($O(N)$), แล้วก็ลูปย่อยวิเคราะห์รอยต่อรอยตัด $k$ ในช่วงความกว้างนั้น ($O(N)$) เมื่อ 3 ลูปวิ่งทำงานซ้อนกัน จะได้ปริมาณรอบการทำงานตีระดับ Big O ได้เป็น **$O(N^3)$**

*(เพิ่มเติม)*
**ความซับซ้อนด้านพื้นที่ (Space Complexity):** **$O(N^2)$**
เหตุผล: ต้องใช้ทรัพยากรไปกับการสร้างตาราง DP ของเรา `dp[i][j]` ขนาด $(N+1) \times (N+1)$ เพื่อจดจำชิ้นส่วนย่อย $Subproblems$ ที่คำนวณไว้แล้วทั้งหมดครับ
