# 📈 Linear Recurrence (ความสัมพันธ์เวียนเกิดเชิงเส้น)

## 1. วิเคราะห์โจทย์ Linear Recurrence
โจทย์ปัญหานี้เกี่ยวกับการหาพจน์ที่ $n$ ของลำดับที่เกิดจากความสัมพันธ์เวียนเกิดเชิงเส้น (Linear Recurrence Relation) ซึ่งมีหน้าตาของสมการดังนี้:

**รูปแบบสมการ:**
* $R(n) = c_1R(n - 1) + c_2R(n - 2) + \dots + c_kR(n - k)$ สำหรับ $n \ge k$
* $R(n) = a_n$ สำหรับ $n < k$

**คำอธิบาย:**
* $k$ คือระดับหรืออันดับของความสัมพันธ์ (Order of recurrence) ซึ่งหมายถึงการคำนวณค่าปัจจุบันต้องใช้ข้อมูลย้อนหลัง $k$ ตัว
* $c_1, c_2, \dots, c_k$ คือค่าคงที่สัมประสิทธิ์ (Coefficients)
* $a_0, a_1, \dots, a_{k-1}$ คือค่าเริ่มต้น (Base cases) หรือเงื่อนไขเริ่มต้นที่โจทย์กำหนดให้ 
* นอกจากนี้ โจทย์ยังต้องการให้คำนวณหาคำตอบภายใต้มอดุโล (Modulo) $32717$ เพื่อป้องกันปัญหาตัวเลขล้น (Integer Overflow) หากค่า $R(n)$ มีขนาดใหญ่มาก

## 2. วิเคราะห์โค้ด Recurrent relation (ความสัมพันธ์เวียนเกิด)
การทำงานของปัญหาความสัมพันธ์เวียนเกิดเชิงเส้น ในมุมมองของ Dynamic Programming คือ:

**Recurrence Relation (หาพจน์ถัดไป):**
การหาค่าพจน์ที่ $i$ (เมื่อ $i \ge k$) จะเกิดจากการนำสัมประสิทธิ์ $c_j$ มาคูณกับผลลัพธ์ย้อนหลัง $R(i-j)$ ทั้งหมด $k$ พจน์ แล้วนำมารวมกัน 
เขียนเป็นสมการในการคำนวณคือ: 
`R[i] = ( c[1]*R[i-1] + c[2]*R[i-2] + ... + c[k]*R[i-k] ) % 32717`

**Base Cases (กรณีฐานเริ่มต้น):**
ข้อมูลตั้งต้น $k$ ตัวแรกจะเป็นค่าตายตัวตามค่า $a_n$
`R[0] = a_0`, `R[1] = a_1`, $\dots$, `R[k-1] = a_{k-1}`

## 3. อธิบายโค้ด
โค้ดภาษา C++ นี้ใช้เทคนิค **Dynamic Programming** รูปแบบวงลูปหรือ Bottom-up เช่นเดียวกับ Fibonacci แต่เป็นรูปแบบที่ถูกทำให้เป็น General Form (ใช้งานได้กับสัมประสิทธิ์และลำดับย้อนหลังที่กว้างขึ้น)

1. **การตั้งค่าเบื้องต้น:** 
   * โค้ดมีการเก็บค่าคงที่ตัวหารเอาเศษ `mod_num = 32717` ไว้ใช้สำหรับการ Modulo
   * ใช้ `ios::sync_with_stdio(false);` และ `cin.tie(nullptr);` เพื่อเพิ่มความเร็วในการอ่าน/เขียนข้อมูล

2. **รับข้อมูลตั้งต้น:**
   * รับค่าระดับ `k` และพจน์ที่ต้องการหา `n`
   * สร้าง Array `coefficients` ขนาด $k$ สำหรับเก็บค่า $c_1$ ถึง $c_k$
   * สร้าง Array `recur` ขนาด $max(k, n) + 1$ เพื่อเก็บค่าของลำดับแต่ละพจน์ $R(i)$
   * ลูปรับค่าฐาน (Base cases) ป้อนลงในตำแหน่ง `recur[0]` ถึง `recur[k-1]` โดยทำการ `% mod_num` เผื่อไว้ทันที

3. **เงื่อนไขตรวจสอบ (Base case check):**
   * ตรวจสอบว่า `n < k` หรือไม่ หากใช่นั่นคือโจทย์ถามหาค่ากรณีฐานพอดี สามารถ `cout << recur[n]` ออกมาได้ทันทีและจบโปรแกรม

4. **ลูปคำนวณ (Iterative Calculation):** 
   * หาก `n >= k` โปรแกรมจะเริ่มรันลูปนอก `i` ตั้งแต่ $k$ ถึง $n$ (หาตั้งแต่พจน์ที่ $k$ ไปจนถึงเป้าหมาย)
   * สำหรับการหาพจน์ใหม่แต่ละบรรทัด จะสร้างตัวแปร `sum = 0` เพื่อสะสมผลบวก
   * ลูปใน `j` (วนรอบคู่กับ $k$) ใช้สำหรับหาพจน์ย้อนหลัง $k$ ตัว โดยคำนวณ `coefficients[j-1] * recur[i-j]` 
   * เมื่อนำมาสะสมใน `sum` จะทำการ `% mod_num` ด้วย เพื่อป้องกัน Overflow 
   * สรุปผลของรอบนั้นยัดกลับลงใน `recur[i] = sum % mod_num`

5. **แสดงผลลัพธ์:** หลังการลูปค้นหาเสร็จสิ้น ค่าสุดท้ายที่ต้องการคือ `recur[n]` ก็จะถูกพิมพ์ออกมา

## 4. Time Complexity
**ความซับซ้อนด้านเวลา (Time Complexity):** **O(n × k)**
เหตุผล: การคำนวณจะมีการวนลูปนอก (หาตั้งแต่พจน์ $k$ ถึง $n$) เป็นจำนวนรอบโดยประมาณคือ $n - k$ รอบ ในแต่ละรอบดังกล่าวจะต้องทำการคูณและบวกร่วมกับลูปข้างในอีก $k$ รอบเสมอ ทำให้ใช้จำนวนรวมของการทำงาน (Operations) เท่ากับ $(n - k) \times k$ ครั้ง ซึ่งรูปมาตรฐาน (Big-O) ของสมการนี้จะตกอยู่ที่ **O(n × k)** 
*ข้อสังเกต: หากโจทย์มีค่า $n$ ที่ใหญ่โตมากๆ (เช่นระดับพันล้าน) โค้ดนี้อาจจะใช้เวลาประมวลผลไม่ทันจำกัดเวลา (Time Limit Exceeded - TLE) ได้ ซึ่งในกรณีนั้นมักจะใช้เทคนิคคณิตศาสตร์ชั้นสูงกว่าเรียกว่า **Matrix Exponentiation** เข้ามาแก้ไขเพื่อให้วิ่งได้ในระดับเวลา **O(k³ log n)***

*(เพิ่มเติม)* 
**ความซับซ้อนด้านพื้นที่ (Space Complexity):** **O(max(n, k))** หรือเรียกอย่างง่ายคือ **O(n)**
เหตุผล: โปรแกรมสร้างเวกเตอร์ `recur` เพื่อเก็บประวัติผลลัพธ์ของตั้งแต่พจน์ที่ $0$ จนถึงพจน์ที่ $n$ ไว้เต็มทุกช่อง (ขนาดสุทธิคือ $n+1$) อย่างไรก็ตามสามารถปรับปรุงลดพื้นที่หน่วยความจำให้เป็น **O(k)** ได้โดยใช้ Sliding Window หรือ Circular Array เพื่อจำแค่ $k$ พจน์ล่าสุดเท่านั้น เนื่องจากเราไม่จำเป็นต้องใช้ผลลัพธ์เก่าที่ห่างเกิด $k$ ในการคำนวณพารามิเตอร์ใหม่
