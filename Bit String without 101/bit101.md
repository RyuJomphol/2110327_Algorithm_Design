# 🚫 Bit String without 101 (สตริงบิตที่ไม่มี 101)

## 1. วิเคราะห์โจทย์ Bit String without 101
โจทย์ต้องการให้เราหาจำนวนรูปแบบของ **Bit String** (สตริงที่ประกอบด้วยเลข `0` และ `1`) ที่มีความยาว $N$ ตัวอักษร โดยมีกฎข้อห้ามเด็ดขาดคือ **ห้ามมี "101" ปรากฏเป็นส่วนประกอบ (Substring)** ในลำดับนั้นเลย 

เนื่องจาก $N$ ในโจทย์สามารถมีค่าที่ใหญ่มาก การใช้ Dynamic Programming (DP) แบบลูปวน `for` ไปทีละตัวเพื่อหาคำตอบจนถึง $N$ (ซึ่งใช้เวลา $O(N)$) อาจจะเกิดปัญหา Time Limit Exceeded (TLE) ได้ ดังนั้นปัญหานี้จึงต้องนำเทคนิคที่ก้าวหน้าอย่าง **Matrix Exponentiation (การยกกำลังเมทริกซ์)** เข้ามาใช้เร่งความเร็วในการคำนวณ เพื่อให้รันเสร็จได้ในพริบตาแม้เงื่อนไขจะใหญ่โตมโหฬาร แถมยังต้อง Modulo `100,000,007` เพื่อควบคุมขนาดตัวเลขด้วย

## 2. วิเคราะห์ที่มาสมการ Recurrence Relation
ในการสร้าง State Machine เราจะแบ่งจัดกลุ่มสตริงตาม "อักขระตัวท้ายๆ (Suffix)" เพื่อใช้เช็คความปลอดภัยเวลาจะต่อตัวอักษรใหม่ แบ่งสถานะ (State) ได้ 3 รูปแบบคือ:
* **State 0 ($v_0$):** สตริงที่ลงท้ายด้วยตัวอักษร `0` แต่ต้องไม่ใช่ `10` (เช่น ลงท้ายด้วย `00` หรือเป็น `0` โดดๆ)
* **State 1 ($v_1$):** สตริงที่ลงท้ายด้วยตัวอักษร `1` (เช่น `01` หรือ `11`)
* **State 2 ($v_2$):** สตริงที่ลงท้ายด้วยตัวอักษร `10` พอดี

เมื่อเราพยายามเติม `0` หรือ `1` ให้สตริงยาวขึ้น ($i+1$) จะเกิดการเปลี่ยนผ่านสถานะดังนี้:
* การจะเป็น **State 0** ตัวใหม่ (`next_v0`): เกิดจากการเอา $v_0$ ไปเติม `0` (ได้ `...00`) หรือเอา $v_2$ มาเติม `0` (ได้ `...100`)
  $\rightarrow \text{next\_}v_0 = v_0 + v_2$
* การจะเป็น **State 1** ตัวใหม่ (`next_v1`): เกิดจากการเอา $v_0$ ไปเติม `1` (ได้ `...01`) หรือเอา $v_1$ มาเติม `1` (ได้ `...11`) 
  *(ข้อควรระวัง: เราห้ามเอา $v_2$ ที่ลงท้ายด้วย `10` มาเติม `1` เด็ดขาด เพราะจะเกิด `101` ทันที!)*
  $\rightarrow \text{next\_}v_1 = v_0 + v_1$
* การจะเป็น **State 2** ตัวใหม่ (`next_v2`): เกิดจากการเอา $v_1$ ที่ลงด้วย `1` มาเติม `0` เท่านั้น
  $\rightarrow \text{next\_}v_2 = v_1$

เราสามารถนำสมการทั้ง 3 ไปสร้างเป็นตารางเมทริกซ์การแปลง (Transition Matrix) $T$ ได้ดังนี้:
$$ \begin{bmatrix} \text{next\_}v_0 \\ \text{next\_}v_1 \\ \text{next\_}v_2 \end{bmatrix} = \begin{bmatrix} 1 & 0 & 1 \\ 1 & 1 & 0 \\ 0 & 1 & 0 \end{bmatrix} \begin{bmatrix} v_0 \\ v_1 \\ v_2 \end{bmatrix} $$

## 3. อธิบายโค้ดและยกตัวอย่าง Testcase
**การทำงานของโค้ด:**
1. โปรแกรมสร้าง `struct Matrix` สำหรับเก็บช่องตาราง 2 มิติขนาด $3 \times 3$
2. จัดเตรียมฟังก์ชัน `multiply` เพื่อใช้คูณเมทริกซ์ 2 ตัว และฟังก์ชัน `matrix_pow` ที่ใช้เทคนิค Divide and Conquer สำหรับยกกำลังเมทริกซ์ให้ประมวลผลได้เร็วสุดขั้วในรูป $T^{exp}$  
3. รับอินพุต $N$ พร้อมสร้าง Base Matrix $T$ จากสมการความสัมพันธ์เวียนเกิดที่วิเคราะห์ไว้
   `T = [1 0 1]`
   `    [1 1 0]`
   `    [0 1 0]`
4. ทำการยกกำลังเมทริกซ์ด้วยคำสั่ง `T = matrix_pow(T, N - 1);` (ยกกำลังแค่ $N-1$ เพราะเริ่มต้นเราอยู่ที่ความยาว $N=1$ แล้ว)
5. เริ่มต้นความยาว $N=1$ เรามี $v_0 = 1$ (มีแค่ "0"), $v_1 = 1$ (มีแค่ "1"), และ $v_2 = 0$ (ยังไม่มี "10") หรือก็คือคอลัมน์เมทริกซ์เวกเตอร์ตั้งต้น `[1, 1, 0]^T`
   ดังนั้น การหาผลลัพธ์ของแต่ละ State ในขั้นตอนสุดท้ายคือการนำบรรทัดสุดท้ายของเมทริกซ์มาคูณกับ `[1, 1, 0]` ซึ่งจะหัก $v_2*0$ ออกไป เหลือแค่ `(T.mat[i][0] * 1) + (T.mat[i][1] * 1)` ตามในโค้ดบรรทัด 69-71  
6. รวมผลลัพธ์ของ 3 สถานะเข้าหากัน `total` แล้วหาเศษตาม Modulo จบการทำงาน

**ยกตัวอย่าง Testcase:**
**Input:** $N=6$
**ลองจำลองผลการเลื่อนเวกเตอร์ (Trace):**
* $V_1$: `[1, 1, 0]` $\rightarrow \text{sum} = 2$ 
* $V_2$: `[1*1+0, 1*1+1*1, 1*1]` = `[1, 2, 1]` $\rightarrow \text{sum} = 4$  
* $V_3$: `[1+1, 1+2, 2]` = `[2, 3, 2]` $\rightarrow \text{sum} = 7$ *(ตรงกับโจทย์ N=3 ในตาราง)*
* $V_4$: `[2+2, 2+3, 3]` = `[4, 5, 3]` $\rightarrow \text{sum} = 12$ *(ตรงกับโจทย์ N=4 ในตาราง)*
* $V_5$: `[4+3, 4+5, 5]` = `[7, 9, 5]` $\rightarrow \text{sum} = 21$
* $V_6$: `[7+5, 7+9, 9]` = `[12, 16, 9]` $\rightarrow \text{sum} = 37$
**Output:** **37** ซึ่งตรงกับผลลัพธ์เป๊ะ 

## 4. Time Complexity
**ความซับซ้อนด้านเวลา (Time Complexity):** **$O(\log N)$**
เหตุผล: แม้ $N$ จะมีค่าสูงเป็นพันล้าน แต่ฟังก์ชัน `matrix_pow` ใช้การยกกำลังแบบแบ่งครึ่ง (Divide and Conquer ทีละส่วน `exp /= 2`) ทำให้จำนวนรอบในการวนลูปทำงานลดลงเป็นแบบ Logarithmic ส่วนการคูณเมทริกซ์ข้างใน $3 \times 3$ ใช้เวลาคงที่ $O(1)$ เสมอ ส่งผลให้ Time Complexity สุทธิเป็น **$O(\log N)$** 

*(เพิ่มเติม)*
**ความซับซ้อนด้านพื้นที่ (Space Complexity):** **$O(1)$**
เหตุผล: การจองหน่วยความจำมีแค่ตัวแปร `Matrix` ที่เป็นอาเรย์คงที่ $3 \times 3$ ช่อง ไม่ว่า $N$ จะเป็นล้านก็ยังใช้เนื้อที่เท่าเดิม ไม่เปลืองหน่วยความจำอย่างแน่นอน
