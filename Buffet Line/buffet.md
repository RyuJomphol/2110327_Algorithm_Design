# Buffet Line

## 1. วิเคราะห์โจทย์ Buffet Line
มีอาหาร `n` ชนิดเรียงบนโต๊ะซ้าย→ขวา แต่ละชนิดมีความอร่อย `d[i]`
มีผู้ร่วมงาน `K` คน แต่ละคนเริ่มตักที่ตำแหน่ง `p[i]` และจะตักต่อเนื่องทางขวาจนได้
ความอร่อยรวมในจานมากกว่าหรือเท่ากับ `w[i]` แล้วเลิก (ตักทีละ 1 ช้อนจากแต่ละชนิด)
เมื่อแต่ละช้อนถูกตักใส่จาน ความอร่อยของช้อนนั้นในจานจะลดลง `m` หน่วย (อาหารบนโต๊ะไม่เปลี่ยน)
รับประกัน `m <= d[i]` เสมอ (ค่าไม่ลบ)

โจทย์: สำหรับแต่ละผู้ร่วมงาน ให้หาตำแหน่งชนิดอาหารที่น้อยที่สุด (ตำแหน่งขวาสุดที่ต้องตักถึง) เพื่อให้
ผลรวมความอร่อย (หลังหัก `m` ต่อช้อนที่ตัก) ≥ `w[i]`

---

## 2. วิเคราะห์ที่มาสมการ / ความสัมพันธ์ (Prefix-sum)
เราสามารถคิดการตักแบบต่อเนื่องจาก `p` ถึง `r` (รวมทั้งสอง) ว่า
- จำนวนช้อนที่ตักจากแต่ละชนิดเท่ากับ `1` ช้อนต่อชนิด → ถ้าตัก `len = r - p + 1` ชนิด
- ผลรวมความอร่อยหลังหัก `m` ต่อช้อน = Σ_{t=p..r} (d[t] - m)

ดังนั้นให้คำนวณ prefix sum ไว้เป็น
```
sum[0] = 0
sum[i] = sum[i-1] + (d[i] - m)   for i = 1..n
```
ถ้าผู้เล่นเริ่มที่ `p` และต้องการอย่างน้อย `w` เราต้องหาค่า `r >= p` เล็กที่สุดที่
```
sum[r] - sum[p-1] >= w
```
หมายความว่า
```
sum[r] >= w + sum[p-1]
```
เพราะ `sum` เป็นลำดับไม่ลด (เมื่อ `d[i] - m` อาจเป็น 0 หรือบวกตามเงื่อนไข `m <= d[i]`) เราจึงสามารถใช้ `lower_bound` บนอาเรย์ `sum` ในช่วง `p..n` เพื่อค้นหา `r` ที่เล็กที่สุดที่พอเงื่อนไข

หากไม่มี `r` ใดที่พอ เฉพาะกรณีนี้โจทย์อาจกำหนดว่าจะไม่มีคำตอบ — ในโค้ดตัวอย่างจะพิมพ์ตำแหน่งที่ `lower_bound` คืน (ซึ่งจะเป็น `n+1`) ดังนั้นต้องสังเกตการจัดการกรณีดังกล่าวตามบริบทโจทย์

## 3. อธิบายโค้ด `buffet_line.cpp` + ตัวอย่าง testcase
โค้ดไอเดียหลัก:
- อ่าน `n, K, m`
- อ่าน `d[1..n]` แล้วคำนวณ `sum[i] = sum[i-1] + (d[i] - m)`
- สำหรับแต่ละคำถาม (มี `K` คำถาม อ่าน `p, w`):
  - คำนวณ `target = w + sum[p-1]`
  - หา `it = lower_bound(sum + p, sum + n + 1, target)`
  - ตอบเป็นตำแหน่ง `(it - sum)` (ตำแหน่ง r)

โค้ดตัวอย่าง (ย่อ):
```cpp
for (int i = 1; i <= n; i++) sum[i] = sum[i-1] + (d - m);
for each query p,w:
  target = w + sum[p-1];
  it = lower_bound(sum + p, sum + n + 1, target);
  print(it - sum);
```

### Testcase จากโจทย์ readme
อินพุต:
```
7 5 2
4 6 2 7 3 5 9
1 1
1 6
1 14
4 7
6 3
```
- คำนวณ `sum[i]` โดย `d[i]-m` = [2,4,0,5,1,3,7]
- `sum` = [0,2,6,6,11,12,15,22]

คำถามทีละบรรทัด:
1) `p=1, w=1` → target = 1 + sum[0] = 1 → lower_bound on sum[1..7] → r=1 → output `1`
2) `p=1, w=6` → target = 6 → r=2 → output `2`
3) `p=1, w=14` → target = 14 → r=6 → output `6`
4) `p=4, w=7` → target = 7 + sum[3] = 7 + 6 = 13 → r=6 → output `6`
5) `p=6, w=3` → target = 3 + sum[5] = 3 + 12 = 15 → r=6 → output `6`

ผลลัพธ์ตามลำดับ:
```
1
2
6
6
6
```
(ตรงกับตัวอย่างในโจทย์)

## 4. Time Complexity
- การคำนวณ `sum` ใช้เวลา `O(n)`
- แต่ละ query ใช้เวลาการค้นหา `lower_bound` ในช่วง `p..n` เป็น `O(log n)` หากใช้ binary search บนอาเรย์ทั้งก้อน (ซึ่งเป็นลำดับ)

ดังนั้นรวมทั้งหมดเป็น **O(n + K log n)** เวลา และ **O(n)** พื้นที่สำหรับอาเรย์ `sum` และข้อมูล

### สรุป
ปัญหา Buffet Line แก้ได้ง่ายด้วยการเปลี่ยนข้อมูลเป็น prefix-sum ของค่า `(d[i] - m)` แล้วใช้ `lower_bound` เพื่อหาตำแหน่งเล็กสุดที่ทำให้ผลรวมถึงเกณฑ์ `w` สำหรับแต่ละผู้ร่วมงาน เทคนิคนี้เร็วและตรงไปตรงมาสำหรับจำนวนคำถามมาก ๆ
